## 已落实的取舍

- 保留故障分类、页面/请求代际隔离、严格请求转义和长度检查。
- Wi-Fi、LLM 新增兼容的 `_ex` 入口，通过调用结果返回细分故障；原接口保留为包装。共享诊断状态进入 `ew_net_state` 互斥快照，删除两模块原有的可变全局 `g_last_fault`。其他操作更新诊断快照不能改写调用方已经得到的故障结果。
- UI 分配/线程创建失败立即发布资源不足提示，不在 UI 线程联网；旧任务回复不能覆盖新页面。
- 选择性保留本机模型迁移、输出预算及配置工具一致性；保留手机网关有界异步模型请求，配置请求不再等待云请求结束。
- 根目录重复 Stage2 副本不合入；热点直连源文件不进入本次默认 dev，原开发区的实验及测试保持原位。
- 雷达判决、独立安全任务、蜂鸣下限、快照和严格 IPC/ACK 核心源码未改变。

## 七项审核问题的修复

1. **UI 资源失败阻塞**：去掉同步网络兜底；新增实际 C 函数故障注入，验证分配/线程失败不触发网络，以及迟到回复被丢弃。
2. **空交付包误过**：目录/ZIP 使用同一验证逻辑，要求主固件、ELF、配置、构建收据、源码、回退镜像和状态文件；重新校验实际固件、源码归档和文件清单。
3. **演示失败误过**：逐轮要求完整成功事件链、正确请求 ID 的有效快照和递增快照序号；失败 complete、空轮次、旧快照均不能通过。物理观测仍为 PENDING。
4. **导出源码缺依赖**：补齐 Stage3 和构建来源模块，统一回归已在真正独立解包的源码目录运行通过。
5. **Wi-Fi 恢复测试编译失败**：更新真实函数提取及必要 fixture，检查 busy 的请求结果和诊断值，未删除原有 AT 互斥/恢复断言。
6. **Windows 路径逃逸**：读取清单目标前拒绝盘符、UNC、反斜杠、父路径及设备名；目录验证拒绝链接/reparse point，ZIP 也使用相同路径规则。测试不连接外部 UNC 地址。
7. **配置泄露**：含非空敏感配置的构建在发布前被拒绝，要求配置脱敏后重新构建。正式封版包装器必须提供匹配的隔离清单，不允许直接改写共享 SDK。没有把复制后删除配置当成清除固件内秘密。

## 构建来源约束

新增 `scripts/host/firmware_provenance.py`。构建前固定源码摘要；构建成功、源码未变且配置通过敏感项检查后，收据绑定源码、ELF、bin 和配置摘要。

seal 必须提供 `source_receipt.json`，过期或不匹配的收据不能把新源码标成旧固件输入。验证过程也检查交付源码归档与收据、清单和固件相互一致。收据用于防止来源混淆，不是代码签名、编译器可信证明或实机身份读回证明。

`build_ew_isolated.sh` 输出匹配的隔离证据和构建收据；`build_stage3_release.sh` 要求 `ISOLATION_MANIFEST`。历史脚本中的本机路径和摘要默认值仍须由本次实际输入覆盖。

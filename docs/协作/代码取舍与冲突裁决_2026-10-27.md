# 代码取舍与冲突裁决

裁决日期：2026-10-27。对象：fork 默认 `2d3fb8f`、Stage2 clean `a9c7693`、Stage3 `90bda35`，以及本机原开发区的后续未提交开发。本地组合审查快照为 `2a8db12`。

**定夺：采用“现有安全主线 + 选择性吸收增量”。不整支覆盖、不把重复目录当成新成果、不以现有验收脚本的 PASS 代替正确性证明。**

本文确定代码取舍和冲突解决方向，不代表七项审核问题已经修复，也不批准向竞赛仓提交。

## 一、必须保留的主线

保留现有 `ew_ld2451` 的雷达解析/判决、`ew_safety` 独立安全任务、蜂鸣安全下限、`ew_snapshot`、`ew_esp_stream`、数字事件 ID、严格 Tool JSON、EWA1 单槽 IPC/ACK 以及现有构建交付保护。

依据是实际接口和代码约束：IPC 注释明确是非阻塞单槽传输；snapshot 注释要求有界、无 I/O 的纯序列化；安全任务不依赖网络/UI 执行判决。候选 Stage2/Stage3 对这些核心文件没有差异。新联网功能不得重算距离、TTC、阈值或降低雷达安全告警。

## 二、逐项保留或暂缓

### 1. Stage2：采用 clean 版，保留增量，修正实现

- 保留 `ew_net_status.[ch]` 的稳定故障枚举、HTTP/CWJAP 分类和用户提示。
- 继续使用 `ew_net_state` 的互斥保护快照作为共享诊断状态；不能照搬两模块 `volatile g_last_fault` 当成某个请求可靠的错误结果。请求的细分错误必须随本次返回值/结果传递，兼容保留现有公开调用接口，必要时新增带结果参数的内部入口或兼容包装。
- 保留 `ew_chat.c` 的任务内问题副本、`g_ask_generation` 和过期回复丢弃。其注释限定为“页面代际”，与网络快照的 generation 不同，不能合并成同一个计数器。
- **不保留** malloc/pthread_create 失败后同步调用 `ew_llm_ask` 的兜底。资源不足时立即发布可重试错误并恢复 UI 状态；禁止把网络长等待放回 LVGL 线程。
- 保留请求长度/转义失败检查和细分 HTTP 错误映射。未接入的脱敏 helper 及其单测不能被当成所有日志已脱敏的证据。
- 根目录旧 Stage2 的 12 个源码/构建文件与 clean 版迁移路径后完全相同：不再次合入活动目录，保留远端分支历史用于追溯即可。

### 2. 本机模型与手机端改进：分别保留

- 保留 `ew_llm.c` 中已有模型配置迁移和 `max_completion_tokens` 限制；迁移仅作用于明确匹配的旧服务端/旧模型组合，不能覆盖用户已选的其他模型或提供商。
- `mimo_configure.py` 与板端默认配置保持一致，不能因采用候选分支而回退本机已测试的配置迁移。本文不把代码中的模型名称当成服务商支持情况的证明。
- 保留 `mobile_prototype_gateway.py` 中有界异步模型请求、重复请求关联、结果缓存和配置请求不被云请求长时间占用的设计；保留相应并发测试。它解决 PC 网关的问题，与板端页面代际隔离不是重复功能。
- 模型迁移、手机异步请求、安全主线分别提交和验证，避免把不同交付单元绑成一次大合并。

### 3. 热点直连：保留实验，暂不进入默认演示链

保留 `ew_direct_http.[ch]`、`ew_wifi_direct.inc`、页面资源和相关测试的原件，后续在独立实验分支保存；本轮不覆盖或清理原开发区。

注释明确直连 owner 在生命周期内独占 `g_at_mu`，统一处理 RX、AT、手机响应和 SSL link 4；`direct_ssl_post` 还检查调用线程必须为 owner。它是传输所有权变化，不能当作单纯多加一个解析源文件。

因此，默认 dev/正式演示先保留现有串口网关路线。直连实验不得开机自动监听，保留显式启动、配对码、请求界限和停止释放模组的约束；在传输所有权、取消/超时、故障码适配、完整构建和真实热点联调验证前，不将其整包并入默认分支。主机 fixture 通过不等于已经完成实机验收。

### 4. Stage3：保留编排，暂缓现有封版入口

- 保留版本化目录/ZIP、主固件与可选 Agent 镜像、已知可用回退镜像、输入清单、SHA256、软件/物理验收分开记录等交付设计。
- 继续复用 `prepare_firmware_candidate.seal` 和 `verify_firmware_candidate.verify`，不复制第二套底层源码和 ELF/bin 校验。
- **不批准当前 `build_stage3_release.sh` 作为正式封版入口**。应接入参数化的隔离、脱敏构建及来源摘要校验；现有 `build_ew_isolated.sh` 有可复用的安全机制，但含日期/路径/输入摘要的本机默认值也不能不经整理就作为通用入口。
- `stage3_delivery.py` 修复之前只保留为开发草稿：校验必须拒绝盘符/UNC/目录逃逸及逃逸链接；要求必需固件、ELF、配置、回退镜像、源码和状态文件；重新验证实际固件；拒绝敏感配置并在脱敏后重新构建；校验构建来源与源码摘要的关联。不能只重写清单或复制后的配置来掩盖问题。
- 保留“三次连续演示”的编排需求，不保留仅按全局日志次数认定通过的判据。逐轮关联请求和事件，要求明确成功结果、有效新鲜快照及无失败标记；复用现有事件链和 SerialBroker/快照校验能力。物理声光、真实雷达和道路结果仍须另行记录。
- 把新增测试和它们导入的模块一起放入源码归档；必须对归档解包后的源码运行统一测试，不能只测试工作区。

## 三、冲突的具体解法

### CMakeLists.txt 与 Makefile：不选整行 ours/theirs

稳定 dev 的两份源清单一致加入 `ew_net_status.c`，保留现有全部安全、快照、IPC、ESP 流等源文件。因为本裁决暂缓直连进入默认分支，**稳定 dev 这轮不加入 `ew_direct_http.c`**。

实验分支以后基于修正后的 dev 再加入 direct HTTP 源文件和所有配套依赖，不能丢掉 `ew_net_status.c`。两套构建入口保持同等功能。

### ew_llm.c：按功能块合并两处冲突

以现有模型迁移、用户自选模型和输出预算逻辑为底座，移入候选的严格转义/长度检查及 HTTP/配置故障分类。迁移完成再生成请求；转义或整体 body 过长时立即失败；错误细节属于本次调用，不从可能被其他操作改写的全局变量推断。

同时合并 `test_llm_runtime.py`，新增故障分类 stub/结果断言和超长输入拒绝验证。不能通过删去模型迁移断言或关闭严格编译让测试通过。

### ew_wifi_at.c/.h：文本能合并仍须适配行为

稳定 dev 本轮只吸收故障分类，不引入直连 owner。直连实验将来整合时，`direct_cached_probe`、`direct_ssl_post` 的提前返回必须同时发布本次传输结果；不能沿用前一次 AT 故障，也不能破坏 owner 对模组的独占。

`test_wifi_recovery.py` 后续整合必须同时保留本机 direct stub 和候选故障状态的必要 fixture/断言；二者不是互斥替代。

### 文档与测试

Stage2/Stage3 README 章节均保留，标明修复和验证状态。PENDING 记录保持 PENDING；保留作者来源和分支历史。已有统一 runner 继续作唯一回归总入口，不新增第二套互不一致的总测试脚本。

## 四、定夺依据与实施次序

本轮补读了相关源码注释、Stage2/Stage3 交付说明和本机 LLM/直连/手机并发测试。统一补齐 GCC 运行库 PATH 后，本机四组定向主机测试均通过：`test_direct_http.py`、`test_direct_owner.py`、`test_llm_runtime.py`、`test_mobile_prototype.py`。这些测试使用合成网络/虚拟模组，未操作真实硬件。

既有审核仍有 5 项功能 P2 和 2 项安全 P2；候选组合规范副本回归仍为 29/30。四组本机测试通过不能抵消候选现有失败和安全问题，也不能当成已经合并后的回归结果。

确定执行顺序：

1. 在修复分支上落实 Stage2 故障分类、旧回复隔离与 UI 非阻塞失败处理，合入模型迁移并补齐相关测试。
2. 单独整合手机异步请求改进；直连实验保持隔离。
3. 修正交付路径边界、敏感配置、必需文件、来源关联和导出依赖，再修演示逐轮判据。
4. 对最终组合源码及其导出副本运行全部无硬件回归；完成真实 ARM/NuttX 链接构建、目标板冒烟与对应验收后，才认定交付候选成立。
5. 通过后仅更新 fork dev。竞赛仓候选另从最新 upstream 挑选已审核改动，人工确认后再提交 PR。

本次仅落地裁决文档和本地测试证据，没有修复产品代码、合入默认分支、远端推送、烧录或占用真实串口。

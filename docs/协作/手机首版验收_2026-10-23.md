## 实际通过的验证

### MuMu：11 个检查点

目标为 `emulator-5554`，MuMu Android12/API32，实际截图为横屏 2560×1440。已安装 APK 并冷启动；应用通过 `10.0.2.2` 连接电脑回环模拟服务。

1. APK 安装与冷启动。
2. 协议握手、明确模拟来源与经 socket 返回的状态。
3. 手动刷新状态。
4. 告警先显示 queued，随后显示 applied，二者不会混淆。
5. 档位切换以模拟服务返回为确认。
6. 输入问题，得到明确注明未调用真实模型的模拟回复。
7. 进入后台关闭连接，回到前台保持手动连接。
8. 后台返回后的手动重连。
9. 服务停止后，界面明确显示连接异常与历史数据。
10. 服务不可用时连接失败，界面仍能操作。
11. 服务重启后恢复连接。

证据：`output/mobile_android/acceptance_v2/acceptance.json`，`passed=true`、`board_tested=false`；同目录有七组 UI XML/截图。初轮自动化工具因每秒刷新无法得到所需空闲窗口，第二轮将验收订阅间隔设为 3 秒后通过；普通服务默认为每秒订阅。没有降低 App 请求/执行验收要求。

### 协议与现有代码

- 模拟服务 **24 项真实 socket 测试通过**：坏 JSON/UTF8/重复键/NaN、长度与版本、参数错误、不支持操作、请求去重与冲突、待执行队列、超时、跨连接重试、订阅/取消屏障、断线与关闭清理。问答始终明确是模拟回复。
- 当前 Host 统一回归 **15/15 suites passed**，包含新增模拟服务套件及原有预警、Agent/IPC、安全线程等测试。证据：`VMware_share/artifacts/mobile_mvp_20261023_host/regression.log`。
- Ubuntu Guest 原有 **8/8** 独立无硬件套件通过；统一入口仍因缺 tkinter 被阻塞。单次 `sudo -n` 需要密码，因此没有安装包、读取密码或重复尝试。临时测试工作区在 `/tmp`，日志在 HGFS。Guest 与 Host 源码不同，不能合并计数，也不能声称同版本双平台完整通过。证据：`VMware_share/artifacts/mobile_mvp_20261023_vm/vm_regression_summary.json`。

## 本轮修复

- App 按连接会话拒绝较旧 event_id 状态，防止不同后台线程的旧订阅快照覆盖最新执行结果。
- 模拟服务跨连接重试同 ID 的订阅/取消会重新设置当前连接状态，避免只重放成功却无订阅；补了对应测试。
- 修正 App/说明中实体手机可直连电脑局域网地址的错误提示：当前服务仅回环监听。
- 构建直接使用已安装 JDK/SDK，不下载 Gradle。资源、Java、DEX、签名与对齐均实际验证，清单最后发布；生成物和本地开发密钥位于忽略目录。

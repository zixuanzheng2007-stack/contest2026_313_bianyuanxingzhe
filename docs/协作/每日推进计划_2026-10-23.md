## 最终交付与验收口径

### A. 手机控制

交付一个可重复构建、可安装的 Android APK 和使用说明。先用 MuMu 验证应用与协议，最终在用户手机和开发板上完成独立无线链路。

首版包括连接/断连、状态与雷达数据、告警演示、受限配置、文本问答、错误显示和重连。参数能力仅在固件真实实现后开放；不能用本地 UI 更新冒充设备设置成功。模拟数据、PC 网关与设备直连必须有明确界面标记。

传输适配共用一套语义：本地设备模拟器用于快速迭代，PC 串口网关用于迁移已有 `@` 控制，ESP32 Wi-Fi/BLE 用于最终独立使用。PC 网关是阶段成果，不是“脱离电脑手机控制”的完成证据。

验收必须覆盖：安装与冷启动；正常请求；超时与错误；断线重连；连续状态；命令只执行一次；排队/执行结果区分；问答失败反馈；数据来源明确。最终真实 Wi-Fi/BLE 链路分别验收。BLE 发现、权限、连接、通知、断线和后台行为需要手机实测。

### B. 固件与智能体优化

保留并验证当前独立安全线程，确保本地雷达和蜂鸣不依赖界面、联网和模型。不要因手机指令、手工清除或测试告警压低正在生效的安全告警。

优先级：

1. 比较官方、fork 接口分支、Host 与 Guest，备份并按模块整合事件契约，修正路径。
2. 统一 ESP32 UART 常驻接收与事件分发，区分 AT 回复、Wi-Fi 数据和 BLE 事件，解决当前清缓冲及同步读抢占问题。
3. 处理手机控制服务与 MiMo 的连接共存：现有单连接 `CIPMUX=0` 不能直接与要求多连接的 TCP 服务共用；设计统一连接编号/所有权与关闭规则后再实现。
4. 将同步网络探测移出 UI 主循环，限制远控队列每轮预算；镜像后台发送采用有限缓冲和丢旧帧策略，不在后台调用 LVGL。
5. 接入真实状态、有限参数和执行结果工具，让问答能够说明真实告警；事件日志和风险简报基于实际记录。不能只靠提示词声称已读取或修改设备。
6. 真机测量触控、网络并发、内存高水位和错误恢复；只有基线支持时再调整输入采样等参数，不先承诺毫秒收益。

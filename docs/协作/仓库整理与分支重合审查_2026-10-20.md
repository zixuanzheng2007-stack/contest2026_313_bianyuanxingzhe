## 4. 与今日工作的重合及冲突

13 个共同修改路径为：

- `app/edge_walker/README.md`。
- `ai_agent_ext/patch_tool_registry.snip`、`ai_agent_ext/tool_approach_alert_ipc.c`。
- `alert_lcd.c` / `.h`、`alert_output.c` / `.h`。
- `ew_agent.c` / `.h`、`ew_agent_tool.c` / `.h`。
- `ew_main.c`、`ew_serial_ctl.c`。

两者都在统一 fake / 雷达 → Agent → Tool → 告警输出并加入事件追踪，属于同一交付工作，不能再作为两套相互独立的成果重复安排。

### 事件与接口

昨日用 `evt-rad-<time>-<seq>` 一类字符串 ID，增加 `source`；今日用 `unsigned long` 数字 ID。昨日 `alert_output_event(id, source, level, reason)` 与今日 `alert_output_event(level, reason, event_id)` 的签名和参数顺序不同，`alert_lcd_show_event` 也冲突。

昨日 Skill 的字符串 ID/source 示例不被今日严格 JSON 入口接受。今日本地执行器为 `ew_agent_tool_execute()`；昨日仍与独立 Tool 同名 `tool_approach_alert_execute()`，直接移入可能重新引入 NuttX flat 链接符号冲突。

### IPC 与执行证据

昨日协议为 `<level> <id> <source> <reason>` 明文；今日为 `EWA1 <numeric-id> <level> <hex-reason>`。生产者和消费者不能混用。

昨日 `queue_alert()` 仍用 `O_TRUNC`，未完整处理短写/失败，且失败后仍可能打印 queued 并返回成功；`poll_request()` 最后仅更新 UI，没有蜂鸣或 applied ACK。其文档中的“蜂鸣与屏幕完整出口”尚未由该路径实现。

今日使用严格解析、非阻塞单槽、临时文件完整写入后原子发布和 ACK；busy 时拒绝覆盖，独立 IPC Tool 成功时只返回 queued，UI/蜂鸣回调执行后才产生 applied，ACK 失败保留占槽。应保留今日实现。软件 applied 仍不等同于实际声音或像素的测量。

### 真实 Agent 框架边界

昨日本地 `ew_agent_emit_decision()` → `ew_agent_proactive_alert_ex()` → Tool 是直接 C 调用；今日 fake/雷达本地链也是直接调用。两者日志中的 Agent 标签都不能单独证明真实 `packages/ai_agent` registry 已调度成功。

今日另有独立 Tool 注册注入、配置与链接符号证据，但 registry → IPC → 执行器的真机闭环仍待验收。昨日主机 `event_chain_smoke` 使用替代板端输出，只能证明本地调度和元数据传递。

### 今日独有及后续事项

今日独有的有效加固包括：严格 IPC/ACK、Tool 符号分离、注册表幂等升级、缺锚点失败、构建成功且非空才导出、失败保留旧交付物、源树/配置摘要，以及 UART3/RX DMA 的实际配置核对。昨日分支没有等价交付保护。

昨日值得吸收的是 source 维度、接收完整 `ew_decision_t` 的统一入口、`ew alert` / `@alert` 也走追踪链、10 事件验收模板与 A/B 边界说明。它们属于待整合增量，并非本轮已经移植完成。

触控响应、远控队列预算和异步镜像只是今日报告中的后续方案，尚未实施，不能列为已经完成的重复优化。

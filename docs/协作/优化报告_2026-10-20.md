## 触控链路与已知时间因素

FT6146 IRQ -> HPWORK I2C 读取 -> NuttX input0 -> LVGL 输入定时器 -> UI 事件 -> 刷新/显示。驱动同时有 20ms LPWORK 兜底轮询；正常 IRQ 路径不必等这 20ms。

当前配置：I2C 默认 100kHz；FT6146 读 5 字节；LVGL 默认输入/刷新周期 33ms；RTOS tick 为 10ms；UI 最大请求休眠为 8ms，受 tick 舍入、调度和前置工作影响，不是端到端上界。

400ms EW_UI_GATE_MS 只在建页后抑制切页请求；期间仍处理页面输入和绘制。门限内的导航请求随后会被重置，可能表现为第一次导航没反应。它不是每次触摸固定等待 400ms，不宜直接取消。

最大风险是 page_pump 在 lv_timer_handler 前同步执行 ew_mirror_tick 和远控命令。@ping/@status 在 UI 线程直接调用 AT；AT 的互斥锁可能被扫描、连接或 HTTP 占用，状态还会连续发送 4 条 AT。ew_serial_ctl_poll 无每轮预算，持续入队时可能挤占 UI。队满打印在队列锁内，串口背压会扩大等待。

## 定量估算（均非实测）

按控制台 1Mbps、8N1（每字节 10bit）计算，390x450 RGB565 全帧加 12B 帧头共 351012B，线缆占用约 3510.12ms；FAST 1/2 缩放 195x225 共 87762B，约 877.62ms。全同色最佳 RLE：全帧约 41.28ms，FAST 约 10.41ms。实际数据介于压缩与 raw 情形，另外还有截图、两遍 RLE、驱动缓冲和调度成本。线缆占用不等于每次 write 的阻塞时间，但持续背压会把工作积压到 UI。

FAST 的 160ms、NORMAL 的 500ms、HD 的 1000ms 是尝试发送周期，不是每帧耗时保证。仅把 UI sleep 从 8ms 改成 1ms，无法消除上述阻塞。

输入定时器 33 -> 16ms 的名义采样等待最多可减少 17ms，均匀相位模型下均值约减少 8.5ms；实际收益受 10ms tick 与其他负载影响。若 I2C 完整事务按约 72bit 估算，100kHz 约 0.72ms；假设硬件明确支持 400kHz，约 0.18ms，理论仅省 0.54ms。未核对器件手册/波形前不建议改总线频率。

## 建议方案与评估

P0：先建立分段测量，分别统计 DOWN 到首次视觉反馈、UP 到目标页首帧，以及丢触和误触。保留 400ms 防抖口径。用 @mirror off 建立本机屏触控基线，再单独开启 FAST/HD 比较，避免把 PC 镜像延迟误当物理触摸延迟。

P1（优先，预计 0.5-1 个工作日，工程估计）：把 @ping/@status 转入现有后台 worker；每轮限制远控处理条数/时间预算；队满日志在解锁后处理。效果是去除可证明的 UI 阻塞源，具体毫秒收益取决于测试负载，不能事先承诺。验证要求 FIFO 次序、down/up 不丢、Wi-Fi 失败仍能触控。

P2（预计 1-2 个工作日，工程估计）：镜像截图只在 LVGL 线程做；后台对独占缓冲编码和发送；最多一帧在途，未完成则跳过新抓帧。用单一发送路径保护帧完整性，不能把 LVGL API 直接搬到 worker。仅将镜像移到本帧绘制后可减少旧页截图挡住已就绪输入，但无法解决整帧发送阻塞。

P3（预计半天调参与复测，工程估计）：仅将实际触摸 indev 的 read timer 从 33 调到 16ms，保留显示刷新周期，观察 tick、CPU 与功耗。全局刷新加快会增加 LCD/CPU 负担，应与输入采样分开评估。

异步镜像资源约束：半帧 raw 缓冲 87750B（约 85.7KiB），全帧 351000B（约 342.8KiB）。Agent 固件链接静态 SRAM 已约 253156B/512KiB（48.29%），剩余数值不是可自由分配堆空间。不得直接额外分配全帧；应核查实际 heap/PSRAM、已有 snapshot 所有权和最大占用。

## 实测验收方案

每个 WARN/CHAT/WIFI 页面至少 50 次独立点击；覆盖离线无镜像、FAST、HD、后台扫描/查询四类场景。分别记录 p50/p95/max、漏触/误触、页面保护期内导航拒绝、UI 最长停顿、队列长度、内存高水位和 I2C 错误。

测量点建议：IRQ/驱动入队、LVGL 读样本、事件回调、目标页创建、flush 完成。使用环形缓冲记录，测试后导出，避免在关键路径持续打印；先查 clock_getres。若要测触碰到可见像素，需高帧率视频或 GPIO/逻辑分析仪配合，固件回调时间不能代替屏幕响应。

建议评审目标（非当前结果）：正常本机触控 DOWN 到首次视觉反馈 p95 <= 100ms；网络任务期间无超过 250ms 的主线程停顿；优化不得增加漏触/误触，也不能改变雷达判决。保护期内导航另计，不混入普通点击延时。硬件到位后先跑基线，再仅改一个因素进行 A/B 复测。

# 手机操控与智能体开发任务书

日期：2026-10-25  
适用范围：边缘行者 Android 手机应用、设备控制协议、应用所需的设备端 Agent/受限 Tool。  
任务模式：按优先级逐项交付；每项必须留下代码/测试证据/明确的未完成项，不得用计划代替实现。

## 1. 目标

让 Android 手机能够通过用户本地网络直接连接边缘行者设备，读取真实状态；在设备端能力与安全条件满足后，执行经过约束的操作，并获得同一请求 ID 对应的最终执行结果。文本问答只能引用设备实际状态，只有真实实现并返回结果的 Tool 才能报告为已执行。

整体交付须分清以下路径和数据来源：

1. `simulator`：软件模拟，所有模拟数据和结果明确标注。
2. `pc_gateway`：手机/模拟器经电脑 TCP 网关访问开发板串口；当前只读，不能作为脱离电脑的完成证据。
3. `device`：手机经本地 Wi-Fi 或 BLE 直接连接设备；只有完成实体设备和实体手机验收后，才可称为真实无线控制。

## 3. 最高优先级任务

### P0：确认并打通设备直连传输

**需求**

- 先只读审查设备侧 AT/UART、Wi-Fi 服务、现有 MiMo/Agent 网络使用和连接所有权，找到唯一的接收/分发入口。网关、Agent、HTTPS、Wi-Fi 服务不能各自竞争读取同一 UART。
- 形成简短接口决策记录：优先实现 Wi-Fi TCP 直连的理由、端口/监听生命周期、配网方式、断线重连、同网段地址发现方式、设备身份校验和认证方案。未经验证不得假定热点、DHCP、AP 隔离或地址分配方式。
- 手机和设备使用版本化、有长度上限的 UTF-8 JSONL 请求协议。握手返回版本、稳定设备 ID、`origin=device`、能力列表、最大消息大小和认证状态。认证/设备身份校验在对外启用真实控制前必须完成；只在隔离实验网络运行的临时阶段也要记录风险和关闭条件。
- 手机能直连时先实现只读 `get_state`、`subscribe_state`，返回真实安全快照、来源、序号/事件 ID、雷达/Wi-Fi链路状态和时间。未知数据用 `null`/明确不可用，不生成默认距离、速度、档位或告警。
- BLE 是独立传输里程碑。需要手机真实 BLE 能力和 GATT 分包、消息号/片段号/总长度、通知、权限、配对/认证、断连恢复测试；不得将 TCP 测试等价为 BLE 测试。

**边界**

- 不更改雷达算法、TTC/目标筛选门限、蜂鸣安全线程或告警优先级来迁就手机联调。
- 不改变/吞掉现有 MiMo 网络路径；在没有连接所有权设计和并发测试之前，不将多个消费者接到共享 UART。
- 不将电脑网关、MuMu、socket 夹具或 ESP USB 串口声称为设备独立无线链路。
- 不保存或打印热点密码、模型密钥、认证密钥；使用现有本地配置来源，测试报告只写脱敏结果。

### P1：实现受限远控及设备端执行确认

仅在 P0 的身份/认证、连接隔离、只读链路稳定后进入。

- 能力以设备端白名单为准；手机不能通过任意 `op`、原始 AT/NSH、shell 或任意参数执行系统命令。
- 先实现低风险、可验证的有限能力，例如读取配置；真实写操作必须逐项定义允许值/范围、持久化语义、冲突策略、限频、权限和回滚行为。
- 对可能影响蜂鸣/屏幕/告警的演示操作必须使用独立 `mobile_test` 来源、最大持续时间和清晰 UI 标签；不得清除、降级、遮蔽或延后真实安全告警。
- 每个操作带唯一 `request_id`。返回 `queued` 只表示接收；只有执行端完成并反馈 `applied` 才显示成功；异常必须 `failed` 并返回结构化错误。相同 ID/内容重试不得重复执行；相同 ID 不同内容返回冲突。超时后先查结果，不自动重放副作用操作。
- 设备端校验参数和授权；App 端再次依据设备声明能力限制控件。客户端隐藏控件不是安全边界。

### P2：让 Agent 问答基于真实快照且安全调用工具

- 注入带 `origin=device`、快照序号、采集时间和有效期的结构化状态。过期、断线、缺测必须显式说明，不可从语言模型补齐数值。
- Tool 仅能调用注册白名单；每个 Tool 定义 JSON Schema/字段范围、权限级别、超时、可取消性、执行结果结构、幂等策略和审计字段。
- 用户输入、网络内容、传感器文本均作为不可信数据；不得覆盖系统任务、要求泄露密钥、越权调用工具或推导“已执行”。
- Agent 输出将“观察事实”“推断”“建议”“已执行结果”分开；操作结果引用对应 `request_id` 和设备最终回执。
- 不开放通用 shell、文件系统、任意 URL、脚本、烧录、重置、关安全线程、修改安全门限等工具。

## 4. 编码要求与工程边界

- 开始改代码前记录当前分支、工作区摘要和目标文件；共享工作区中保护现有未提交修改，不 `reset`、不强制覆盖、不盲目合并 upstream/fork。
- 每次只做一个可审查增量。先写失败测试或协议夹具，再实现；修改后跑与改动相称的测试和完整 Host 回归。测试/构建结果及日志写入唯一的新输出目录，不覆盖以前的 APK、固件、日志或验收报告。
- Android 继续使用仓库现有纯 Java/平台 API 构建约束，维持网络 I/O 不阻塞 UI；消息大小、连接数、队列、在途请求、订阅频率、重连次数和等待时间均有明确上限。
- C 侧使用现有安全快照和 Agent/IPC 接口；避免新增并发 UART 读者、动态无界内存、无限等待、无上限队列、阻塞 UI/LVGL 或安全线程。
- 新增接口必须有错误码、请求/结果示例、能力协商说明、超时/去重/断线语义和版本兼容策略。不可识别版本/字段采取安全失败，不放宽解析来“让测试通过”。
- 日志不得包含凭据、完整热点信息、用户个人数据或可能持续识别个人的设备标识。构建清单记录源码/配置/APK摘要和工具版本。
- 物理板只在确认端口、固件版本、无人占用、备份与测试动作后操作。手机安装/应用 UI、MuMu、网关夹具、COM 实板、独立 Wi-Fi、BLE、VM 交叉编译分别记录，禁止跨类别互相替代。
- 通用串口/供电稳定性工作属于独立任务；本任务仅在手机/Agent接口必需处依赖其已确认的接口，不重复修改其所有权文件。若不可避免发生文件冲突，先停在只读评估并记录冲突，不并行改同一模块。

## 6. 里程碑定义

1. **M0 可审查接口设计**：UART/无线连接所有权与协议决策有文档；测试计划与设备能力表不再把模拟器能力当设备能力。
2. **M1 实际设备只读 Wi-Fi**：T05-T08 在实体手机与实体设备通过，拔除电脑网关仍能更新真实状态；完成 Host 回归和固件交叉编译。
3. **M2 受限控制**：T09-T12 通过；设备端身份、白名单、幂等、确认与告警保护有证据。未经M1/M2验证保持控件禁用。
4. **M3 Agent 实况问答**：T13-T14 通过；无虚构状态、无越权工具；工具审计关联真实事件和请求。
5. **M4 BLE（若列入演示）**：T15 在实际手机/板上通过；否则明确标记未实现，不能与 Wi-Fi 验收混写。
6. **M5 演示候选**：适用测试通过、失败可恢复、固件/APK和校验材料归档；30分钟长稳及离线行为通过后才可标记候选。

## 7. 给执行智能体的开工指令

从本任务书和当前工作树开始，先只读核对现状与任务冲突，列出当前最高优先级的一个具体增量。完成后再按“需求/代码边界/测试用例/验收结果/剩余项”报告。只要实体手机、热点、无线认证或真实写操作缺少必要前提，就保持相应能力关闭并继续完成不依赖该前提的工作；不要把等待用户实测当作停止其它工作的理由。

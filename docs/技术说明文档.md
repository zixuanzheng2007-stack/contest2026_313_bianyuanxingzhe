# 边缘行者 · 技术开发方向说明与规划

> 产品：边缘行者（行人侧后电自/电动车接近预警 · 环状可穿戴）  
> 赛事：2026 openvela AI 硬件开发者大赛  
> 用途：统一技术方案、工程节奏与分工；可作为组内计划与导师同步材料  
> **版本：1.3** · **文档日期：2026-08-05** · **最后更新：2026-08-25**
---

## 1. 方向说明

### 1.1 要做成什么

在腰带 / 腰包 / 帽圈等环状穿戴形态上，用毫米波感知侧后接近的静音电自或电动车，通过震动或短耳标提醒行人。系统跑在 **openvela + ai_agent** 上：本地完成探测与告警判决，Agent 负责阈值主动触发与 Tool 执行，大模型只做配置与简报。

面向城市步行通勤者，并对听障、视障做反馈特化。明确边界：不替代盲杖、导盲犬，不对标车端开门预警或骑行座杆雷达同等体验。

### 1.2 为何选这一技术路线

| 备选路线 | 结论 |
|----------|------|
| 纯声学识别电自 | 静音场景漏报高，不作主路径 |
| 板载摄像头主探 | 延迟、功耗、遮挡与穿戴朝向不稳，不作主路径 |
| 云端大模型判是否告警 | 延迟与断网风险不可接受，赛题也不鼓励 |
| **毫米波 + IMU + 本地策略 + ai_agent 执行** | **定案**：低延迟、可离线、贴赛题「主动+Tool」 |

### 1.3 成功标准（工程验收口径）

1. 直线辅路：侧后接近目标能在合理距离内给出可感知提醒。  
2. 路口 / 转弯：有降敏策略，避免持续乱震。  
3. 断网：接近检测与震动闭环仍可用。  
4. 赛题：真机 openvela、≥1 Skill、阈值/事件主动 + Tool 执行；语音若启用则唤醒词为「你好，openvela」。  
5. 演示：有样机形态 + 路测或可控场景视频。

## 2. 技术方案（定案）

### 2.1 系统架构

```
手机 Companion ──BLE──► 导航场景标签（只调灵敏度）
HLK-LD2451 ──UART──► 雷达解析 / 目标跟踪
IMU ──I2C/SPI──► 场景识别（走 / 停 / 转弯）
                │
                ▼
         策略引擎（TTC / 门限 / 降敏 / profile）
                │  越限
                ▼
         ai_agent 主动触发 → Tool（震动 / 耳标 / 日志）
                │
         Skill（偏好 · 导航同步 · 听障/视障 · 简报）
                │
         云端 Xiaomi MiMo（仅语义配置与简报，不参与告警判决）
```

### 2.2 硬件方案

| 层级 | 选型 | 说明 |
|------|------|------|
| 主控 | **SF32LB52 LCD（DevKit-LCD）** | 赛方审核要求 WiFi 可拓展；同族芯片、接口更全，可扩 SDIO WiFi；LCD 便于调试/状态显示 |
| 主传感器 | **HLK-LD2451** | 24G 后方来车毫米波，UART；勿用人存在雷达冒充 |
| 辅传感器 | IMU（I2C/SPI） | 转弯、静止等场景降敏 |
| 联网 | **SDIO WiFi 扩展**（按模组版本） | 服务 ai_agent / MiMo；安全告警仍断网可用 |
| 执行器 | 震动马达（PWM/GPIO） | 通用与听障主反馈 |
| 可选 | 骨传导模组 | 视障短耳标；非 MVP 阻断项 |
| 手机 | BLE Companion | 同步路口等标签，不上传完整轨迹为默认 |

形态：竞赛原型取 **腰包主脑 + 外挂雷达**（LCD 可显告警档）；量产可再缩无屏腰扣。原黄山派仅作低功耗形态参考。不选用已发完的 STM32H750B-DK，也不以过大边缘 AI 板作腰戴主控。详见 `docs/开发板更换分析.md`。

### 2.3 软件方案

| 模块 | 技术选型 | 职责 |
|------|----------|------|
| OS / 框架 | openvela（大赛分支）+ 板级 BSP | 驱动、任务调度、联网可选 |
| 安全环 | C/C++ | 雷达解析、跟踪、TTC/门限、IMU×导航融合、输出告警等级 |
| Agent | openvela **ai_agent** | 阈值越限主动；Tool 执行；Skill 配置 |
| 云端 LLM | Xiaomi MiMo（大赛 Token） | 偏好说明、无障碍配置、风险简报 |
| 交互 | CLI / 语音 / WebSocket 择一或组合 | 演示与调参 |

**Skill（计划）**：`approach-guard`、`nav-sync`、`a11y-hearing`、`a11y-vision`、`risk-brief`  

**Tool（计划）**：`haptic_alert`、`earcon_alert`、`set_profile`、`set_nav_bias`、`log_event`

### 2.4 关键策略（不可再摇摆）

1. **雷达主探**：发现电自不依赖是否发声。  
2. **导航只调敏**：不下发「立刻震动」；无导航时退回 IMU + 默认档。  
3. **IMU 与导航冲突时信 IMU**。  
4. **判决在端侧**：LLM 不算 TTC、不决定是否告警。  
5. **告警经 Agent Tool 落地**，满足赛题「主动 + 执行」。  
6. **探测目标距离**：以约 15–40 m 可用为目标，不对标 140 m 级骑行雷达体验。

### 2.5 仓库与合规

- 专属仓库，建议 Apache 2.0。  
- 真机跑通 ai_agent；断网安全环可独立演示。  
- 板型申领与「环状穿戴 + 外挂雷达」故事保持一致。

- **功能砍刀顺序**（进度紧张时）：先砍有声辅检与双马达编码 → 再砍骨传导 → 再砍导航 BLE（保留 IMU 降敏）→ **绝不砍** 本地告警与 Agent Tool 执行。

## 4. 分工安排

按角色划分；人数不足时一人可兼两角，但 **安全环负责人与 Agent 负责人建议分开**，避免「只会聊天不会震」或「只会震不会 Skill」。

### 4.1 角色与职责

| 角色 | 主责 | 协同 | 交付物 |
|------|------|------|--------|
| **硬件与结构（H）** | 主控供电、UART/I2C/PWM 接线、雷达安装朝向、震动马达驱动、外壳/腰带固定、续航与温升初测 | 与 F 对接口表；与 T 对佩戴舒适度 | 原理图/接线表、样机结构、物料清单 |
| **固件与感知（F）** | openvela 板级、雷达解析、跟踪/TTC、IMU 场景、策略引擎、断网闭环 | 向 A 提供告警事件与等级接口；向 H 反馈驱动需求 | `radar` / `imu` / `policy` 模块、台架测试报告 |
| **Agent 与云端（A）** | ai_agent 集成、Tool/Skill、MiMo 配置对话、语音或 CLI 渠道、合规检查 | 消费 F 的越限事件；不改写本地判决逻辑 | Skill 包、Tool 实现、Agent 演示脚本 |
| **应用与体验（P）** | Companion BLE 协议与简易 UI、profile 文案、演示脚本、答辩 PPT/视频剪辑 | 与 F 对导航标签字段；与 T 对场景剧本 | Companion、演示分镜、对外介绍稿 |
| **测试与合规（T）** | 用例设计、误报/漏报记录、断网与赛题清单核对、路测组织 | 全程卡出口标准 | 测试用例表、问题单、验收签字记录 |

说明：若仅 2～3 人，建议合并为 **H+F**、**A+P**、**T 轮值**；T 的出口检查不可省略。

### 4.2 阶段 × 角色矩阵（R=主责，S=协作）

| 阶段 | H | F | A | P | T |
|------|---|---|---|---|---|
| 0 立项环境 | R | R | S | S | S |
| 1 感知闭环 | R | R | — | S | R |
| 2 降敏策略 | S | R | — | S | R |
| 3 Agent 无障碍 | S | S | R | S | R |
| 4 样机路测 | R | S | S | R | R |

### 4.3 协作约定

1. **接口先于实现**：阶段 0 冻结 UART 引脚、告警等级枚举、BLE 标签字段、Tool 名称。  
2. **日更短同步**：每天 10～15 分钟对齐阻塞项；以问题单为准，不靠口头记忆。  
3. **主分支保护**：感知与 Agent 分分支开发，合并前必须通过「断网震动」冒烟用例。  
4. **变更控制**：改主传感器、改「云端参与告警」、改主控板型，须全员确认并更新本文档版本记录。

### 4.4 建议周节奏（示例）

| 工作日焦点 | 内容 |
|------------|------|
| 周一 | 本周目标与接口确认 |
| 周二～四 | 按角色冲刺；周三中途联调一次 |
| 周五 | 出口演示 + 问题单收敛 + 更新风险 |
| 周末 | 可选路测或结构件；不堆新功能 |

## 5. 风险与对策（开发侧）

| 风险 | 对策 |
|------|------|
| 路口误报导致体验崩 | 阶段 2 必修；进度紧则加强 IMU，导航可延后 |
| 雷达朝向/遮挡 | H 阶段 1 做安装夹具；路测前做朝向标定 checklist |
| 续航不足 | 间歇探测 + 场景休眠；演示用外接电源兜底 |
| Agent 集成拖期 | 先 CLI + 单 Skill + 单 Tool，再补语音与多 Skill |
| 板型到货延迟 | 先用 USB-TTL 跑通 LD2451 协议；板到后迁 DevKit-LCD UART/WiFi |

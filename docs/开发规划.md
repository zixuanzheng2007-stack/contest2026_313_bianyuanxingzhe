## 第 10 项 · 团队作品开发规划（必填）

### ① 项目名称与一句话定位

项目名称：边缘行者。面向城市步行通勤者，以及听障、视障出行人群，解决静音电自、电动车从侧后接近时难以察觉的问题。作品做成腰带、腰包或帽圈等环状可穿戴，用毫米波雷达主动感知，以震动或短耳标提醒，作为出行辅具增强，不替代盲杖、导盲犬，也不对标车端开门预警。

### ② 目标开发板及选板理由

目标开发板：**SF32LB52 LCD（DevKit-LCD）**。该板与思澈 SF32LB52 同族，已适配 openvela（板级 `sf32lb52_devkit_lcd`），接口丰富，**可扩展 SDIO WiFi**，满足云端 ai_agent / MiMo 联网演示；自带 LCD，便于调试与告警档位显示。竞赛原型取腰包主脑 + 外挂雷达形态，量产可再缩无屏腰扣。主感知自备海凌科 HLK-LD2451（24G 后方来车毫米波，UART 接入）。不选用已发完的 STM32H750B-DK，也不选体积过大的待适配边缘 AI 板作主控。原黄山派仅作低功耗形态参考，不再作为申领首选。

### ③ 核心功能需求列表（含所需硬件能力）

一是侧后接近检测与告警：雷达给出距离、速度等信息，端侧做接近判断并触发提醒，需 UART 接雷达、GPIO/PWM 驱震动马达。二是场景降敏，减少路口误报：IMU 识别转弯、静止等状态，手机步行导航经 BLE 下发路口等标签，只调节灵敏度，需 I2C 或 SPI 接 IMU、蓝牙 BLE，**Wi‑Fi（SDIO 扩展，服务 Agent/简报）**。三是分级反馈：通用模式腰震；听障强化震动编码；视障短骨传导耳标并与盲杖并用，需 PWM/GPIO，视障模式另需音频输出；LCD 可选显示告警档。四是基于 openvela ai_agent 的主动执行：接近越限后主动触发，由 Tool 执行震动或记日志，并配套接近防护、导航同步、听障/视障无障碍及风险简报等 Skill。五是断网仍可本地告警，云端只做配置与简报，不参与是否告警的判决。主路径不依赖板载摄像头。

### ④ 各功能技术方案（端侧 / 云端）

感知与安全判决放在端侧：基于大赛 openvela 分支与 DevKit-LCD 板级 BSP，用 C/C++ 完成雷达解析、接近估计、IMU 与导航融合策略；告警通过 ai_agent 的 Tool 落地执行。Agent 使用官方 ai_agent 框架，自定义 Skill 以 Markdown 部署；可用 CLI、语音（唤醒词「你好，openvela」）或 WebSocket 任一渠道交互；开发期经 WiFi 连接云端。云端采用大赛发放的 Xiaomi MiMo，仅用于偏好说明、无障碍配置与风险简报文案，不参与实时告警判决。手机侧以轻量 Companion 经 BLE 同步导航场景标签。自备物料包括 LD2451、震动马达，视障模式可选骨传导模组，以及电池与腰包外壳。

## 第 10 项 · 合并粘贴版（若表单仅一个大文本框）

项目名称：边缘行者。面向城市步行通勤者及听障、视障出行人群，解决静音电自、电动车从侧后接近时难以察觉的问题；以腰带、腰包或帽圈等环状可穿戴形态，用毫米波主动感知并以震动或短耳标提醒，作为辅具增强，不替代盲杖、导盲犬或车端开门预警。

目标开发板为 **SF32LB52 LCD（DevKit-LCD）**：同族 SF32LB52、已适配 openvela，**可扩展 SDIO WiFi**（响应审核联网要求），LCD 便于调试；竞赛取腰包主脑形态。外挂自备 HLK-LD2451 毫米波（UART）。不选用已发完的 STM32H750B-DK。

核心功能包括：侧后接近检测与告警（UART + PWM/GPIO 震动）；IMU 与导航 BLE 场景降敏（I2C/SPI、BLE、Wi‑Fi）；听障强震动 / 视障短耳标分级反馈（PWM，可选音频）；openvela ai_agent 阈值主动触发并由 Tool 执行；断网仍可本地告警。主感知不依赖摄像头。

技术方案上，端侧跑 openvela 与 ai_agent，本地完成雷达解析、接近估计与融合策略；云端 Xiaomi MiMo 仅做配置与简报；手机 BLE 同步导航场景标签。自备雷达、震动马达及可选骨传导与外壳。

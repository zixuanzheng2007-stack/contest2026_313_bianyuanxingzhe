# 手机控制协议 v0.1（实现前草案）

日期：2026-10-23。状态：Android App 和本地设备模拟器首版已实现并通过 MuMu 验收；本文仍是待与固件及 fork 的 `event_id + source` 接口核对的协议草案，尚不表示真实无线固件已实现。

## 目标与传输

统一 Android App、设备模拟器、PC 串口网关和 ESP32 独立 Wi-Fi/BLE 的业务语义。测试链路逐级替换，不让 App 页面依赖原始 AT 或 NSH 命令。

网络首版采用有长度上限的 UTF-8 JSON 行消息；BLE 后续增加带消息号、片段序号和完整长度的分包层，不能假设一个 JSON 能装入一个 GATT 写入。握手返回协议版本、设备能力、消息大小与数据来源。网络建立/配对、认证和连接所有权须在真机无线接入前明确实现。

## 请求、确认与事件

请求示例：

```json
{"v":1,"id":"app-001","op":"get_state","args":{}}
```

最终应答示例：

```json
{"v":1,"id":"app-001","type":"result","ok":true,"data":{"origin":"simulator","connected":true}}
```

异步命令允许先返回 `type=accepted`、`stage=queued`，之后必须有同请求 ID 的最终 `type=result`、`stage=applied|failed`。排队不等于物理执行；软件 applied 也不等于声学/光学实测。超时或重连后先查结果，不能无条件重发有副作用的命令。执行端维护有限去重记录；同 ID 不同内容返回冲突。

设备事件使用自己的单调 event_id，保留原始 source；请求 ID 与事件 ID 分开。需把移动端动作关联到原有事件时，显式记录 request_id，不重写雷达事件来源。

失败统一包含明确 error.code 和用户可读 message；不把错误编码成成功文本。常见错误：unsupported、invalid_argument、busy、timeout、not_connected、not_configured、execution_failed、id_conflict。

## 首版操作

- `hello`：返回版本、设备标识、origin、capabilities、最大消息长度。origin 至少区分 simulator、pc_gateway、device。
- `get_state` / `subscribe_state`：真实状态快照与订阅。设计映射到 `ew_safety_snapshot` 等已有模块；返回距离/速度/告警、雷达链路、Wi-Fi、最近事件与时间戳，无法获得的字段必须明确不可用，不能填伪造数值。
- `test_alert`：受限时长的告警演示，source 标为 mobile_test；不能关闭或压低正在生效的真实安全告警。
- `get_config` / `set_profile`：能力协商确认后才开放。固件尚未支持时返回 unsupported，不在 App 内假装设置成功；范围、持久化和实际生效值由设备校验并返回。
- `ask`：文本问答，使用独立请求和完成结果。未联网、未配置或模型失败要明确反馈；设备状态解释必须注入真实快照，工具执行必须由允许列表和设备端验证。
- `get_events`：后续阶段，分页读取真实事件记录；没有持久化记录时明确返回该能力不支持，不能用演示事件代替历史。

连接管理、解析与命令执行各有唯一所有者。JSON 长度、队列、去重表、订阅频率与在途请求数均有上限；网络/模型任务不阻塞安全线程和 LVGL。ESP32 数据只能由统一接收入口解析，不能让 BLE、网络服务和 HTTPS 各自读取同一个 UART。

## 模拟器验收与真机边界

自动覆盖正常请求、坏版本/坏 JSON/过长输入、不支持操作、繁忙、最终失败、重复请求、ID 冲突、订阅取消、断线恢复，以及“已接收但未执行”的显示。模拟后端可注入延迟、丢连接和乱序事件，数据必须标为 simulator。

MuMu 验证 APK 安装、页面、输入、网络请求和错误状态；本机当前 Android12 实例缺少 BLE feature，真实扫描、配对、GATT通知及后台恢复另用用户手机与 ESP32 验证。PC 网关测试也不能算独立无线链路完成。

## 首版实现与证据

2026-10-24 增补：APK 0.2.0 已支持只读 pc_gateway 来源，板端新增 `@snapshot <request_id>`；网关只开放 hello/get_state/subscribe_state。详情见 `docs/协作/手机只读网关验收_2026-10-24.md`。

网关的 data 保留实际 event_id，以递增 snapshot_seq 进行状态排序；事件 envelope 的 event_id 对应 snapshot_seq。range_m/speed_kmh 可为 null，profile 为 null。`radar_link` 取值含 `waiting`（从未收到 UART 字节）、`no_frame`（有字节但尚无合法 LD2451 帧，对应板端 NO FRAME）、`ok`、`stale`、`error`。updated_ms 与 clock=device_monotonic 保留设备时钟，另加 received_at_ms 标识网关接收时间。串口 ID 含随机会话 nonce，按本次匹配响应；设备重启时全部旧连接失效，新会话重新建立顺序。只读请求重复 ID 会重新读新鲜数据，ID 仍用于内容冲突检测；这与模拟器副作用操作的结果缓存有意不同。

- Android：`mobile/android/`；构建：`scripts/host/build_mobile_apk.py`。
- 模拟后端：`scripts/host/mobile_device_simulator.py`，仅回环监听；协议回归 `scripts/host/test_mobile_device_simulator.py`，24 项真实 socket 测试通过。
- 同 ID 的订阅重试作用于当前连接，取消确认与后续事件之间有发送屏障；跨重连重复动作通过有界缓存去重，缓存过期后不承诺永久 exactly-once。
- Android 每连接会话拒绝较旧 event_id 状态，避免异步订阅旧快照覆盖较新的执行确认；重连重置顺序标记，同序号仍可刷新时间和订阅标记。
- App 的设备来源目前接受 simulator 和只读 pc_gateway，尚不接受 device；不能把设备端声明直接作为真实控制验收。模拟问答明确不调用模型。
- MuMu 界面验收：`scripts/host/mobile_mumu_acceptance.py`，11 个检查点通过；详情见 `docs/协作/手机首版验收_2026-10-23.md`。

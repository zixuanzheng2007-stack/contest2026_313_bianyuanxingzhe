## 总览

| 部分 | 类型 | 名称 | 一句话目标 | 建议负责人 |
|------|------|------|------------|------------|
| **一** | 硬件 | 整机硬件落地 | 供电、接线、WiFi 冒烟、结构、样机可测 | 硬件 / 结构 |
| **二** | 软件 | 感知安全环 | 雷达解析 → 判决 → 震动（断网可用） | 固件 / 嵌入式 |
| **三** | 软件 | Agent 与赛题 | 主动触发 + Tool 执行 + Skill（可联网演示） | 应用 / Agent |

板未到时，部分二 / 部分三分别对应 **无板 A / 无板 B**（见下一节）；板到后迁驱动与真机联调。

```
部分一 硬件落地 ──接线表 / 样机──► 部分二 感知安全环 ──告警事件──► 部分三 Agent 与赛题
                 ▲                        │                              │
                 │                        └──────── 软件联调 / 冒烟验收 ──┘
         （可并行）无板 A / 无板 B 先在主机与模拟器推进
```

**原则**

- 硬件单独成块，一次把「能测的物理样机」交付干净（含 WiFi 扩展冒烟）。  
- 软件拆成两条线：安全判决（部分二）与赛题 Agent（部分三），避免混成「又震又聊天」。  
- **无板阶段也按这两条线拆开两人（或一人分时段）推进，不要混在一个 backlog。**  
- 部分二、部分三可并行写代码；部分三联调依赖部分二的告警接口。  
- 初期不展开：完整导航 App、骨传导、第二雷达对照。

## 部分一 · 硬件落地（全部硬件工作）

### 1.1 目标

交付一台可联调的物理样机：**SF32LB52 LCD** 上电正常，**SDIO WiFi（或等效扩展）可冒烟**，LD2451 有数据，马达能振，朝向固定，组内接线表冻结。

### 1.2 任务清单

| 序号 | 任务 | 交付物 | 完成标准 |
|------|------|--------|----------|
| H1 | **按审核改申领 SF32LB52 LCD**；到货 / 上电确认 | 到货记录 | 板可上电、USB 调试口可用；LCD 可点亮（可选冒烟） |
| H1b | 确认 WiFi 模组版本（如 -A / SDIO）；天线到位 | WiFi 备注 | `ifconfig` / 联通性冒烟通过，或明确外挂方案 |
| H2 | 采购齐套：LD2451、5V 升压、杜邦线、排针、震动马达、线材 | 采购勾选表 | 物料到齐（见采购文档） |
| H3 | 雷达供电：板载 5V / 升压 → LD2451；共地 | 供电接线图 | 雷达工作电压 ≥4.9 V，电流正常 |
| H4 | 雷达信号：UART2 引出；TX↔RX；**不占用** Debug UART | **接线表 v1** + 照片 | 手机 APP 或 USB-TTL 可见目标数据；脚位按 DevKit-LCD 原理图 |
| H5 | 震动马达接到 PWM/GPIO（注意与 UART2 脚不冲突） | 马达接法说明 | 可手动点振 |
| H6 | 雷达朝向与固定（腰带/腰包夹具，天线朝侧后） | 朝向 checklist + 样机照片 | 遮挡可控、方向可复现 |
| H7 | 焊接项落实：升压线、模组插针（若无针）、开关电源（可选） | 焊接点清单 | 无虚焊、抗拉扯 |
| H8 | 样机冒烟：上电顺序、发热、续航粗测 | 硬件冒烟记录 | 连续工作 ≥30 min 无异常重启 |

**板未到也可推进**：H1 跟进、H2 采购、H4 用 USB-TTL 先验模组、接线表草稿（脚号留空）、朝向 checklist。

### 1.3 硬件硬约束

- 通信：**UART TTL 3.3 V**；雷达接 **UART2**（具体脚号以 DevKit-LCD 原理图为准）；Debug UART 不给雷达。  
- 供电：LD2451 必须 **5 V**，禁止直连锂电池。  
- 联网：开发期具备 **WiFi 拓展**（审核要求）；**告警安全环仍断网可用**。  
- 连接电脑：Type-C **数据线** 插板载 **USB to UART**（A-to-C / C-to-C 均可）；Windows 需 CH34x 驱动。  
- 焊接：模组无插针则必须焊针；升压进出线建议焊牢；详见接线手册。

## 部分二 · 软件 · 感知安全环

> 板未到：执行 **无板 A**。板到后：把主机逻辑迁到 `sf32lb52_devkit_lcd`，换真 UART2 / PWM。

### 2.1 目标

在 **SF32LB52 LCD / openvela（`sf32lb52_devkit_lcd`）** 上实现端侧闭环：**收雷达帧 → 过滤/TTC → `alert_level` → 震动**；断网仍可用。本部分**不负责**大模型对话。

### 2.2 任务清单

| 序号 | 任务 | 交付物 | 完成标准 |
|------|------|--------|----------|
| S2.1 | 搭建 openvela DevKit-LCD 工程（大赛分支）、烧录、NSH 验证 | 编译/烧录说明 | 板能进系统、UART/PWM 可访问 |
| S2.2 | UART2 驱动与 LD2451 协议解析 | `radar_ld2451` | 稳定输出距离/速度/方向/角度 |
| S2.3 | 目标过滤（只靠近、最小速度、SNR） | 参数表 | 远离/静止不明显误报 |
| S2.4 | 策略引擎：距离门限 / 粗 TTC → 告警等级 | `policy` | NONE/SOFT/STRONG/EMERGENCY 可区分 |
| S2.5 | 震动编码与驱动 | `haptic` | 等级与震感一一对应 |
| S2.6 | 运行日志（摘要 + 判决） | 日志样例 | 台架可复盘 |
| S2.7 | （可选）LCD 显示当前告警档位 | 简易 UI | 便于台架调试（非安全环阻断项） |
| S2.8 | （可选并行）板载 IMU 走/停/转弯粗状态 | `imu` 初版 | 为后续降敏留接口 |
| S2.9 | 台架/走廊联测（配合硬件样机） | 测试记录 | 接近可复现震动 |

### 2.3 建议初值

| 参数 | 初值 |
|------|------|
| 雷达最远距离 | 40 m |
| 检测方向 | 只靠近 |
| 最小速度 | 5 km/h |
| 软 / 强 / 紧急 | 约 25 m · 15 m · 8 m（或对应 TTC） |

### 2.4 向部分三提供的软件接口

```text
alert_level: NONE | SOFT | STRONG | EMERGENCY
event: approach_threshold_exceeded
payload: range_m, speed, azimuth, ttc_s, timestamp
```

判决只在端侧完成；**禁止**在本部分调用 LLM 决定是否告警。

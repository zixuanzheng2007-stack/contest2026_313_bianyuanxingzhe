# 主程序 / openvela 烧录：离开测试界面

## 为什么屏一直停在「测试界面」

当前烧进去的 openvela 固件在开机脚本里会跑 **`lvgldemo`**（LVGL 官方 Demo），看起来就像测试/演示 UI，**不是**边缘行者主界面。

要离开它，需要：

1. 编进带 **`ew`（edge_walker）** 的 `nuttx.bin`  
2. 开机改成 **`ew boot`**（深蓝待机），不要自启 `lvgldemo`  
3. 用 **sftool** 烧到板子  

> 若从未烧过 openvela，屏上也可能是 **SiFli 出厂 Solution**；同样用下面步骤刷成你们的 `nuttx.bin` 即可覆盖。

---

## 一、openvela + 主程序是什么关系

| 名称 | 含义 |
|------|------|
| **openvela** | 整包系统（NuttX + 板级 + 驱动）→ 产物 **`nuttx.bin`** |
| **主程序 `ew`** | 编进同一镜像里的 NSH 应用（告警、假数据、填色） |
| **烧录** | 把 **整份** `nuttx.bin` 写到 Flash `@0x12010000`（不是单独再烧一个「主程序文件」） |

---

## 二、Ubuntu（VMware）重编（去掉测试 UI）

仓内已改：

- `board_overlay/.../rcS.user` → `ew boot`  
- `VMware_share/build_ew_main.sh` → 编译时删掉 `lvgldemo`、写入 `ew boot`

在 Ubuntu 全量工程根目录：

```bash
bash contest2026_313_bianyuanxingzhe/VMware_share/build_ew_main.sh
```

成功后共享盘应有：

`VMware_share/artifacts/nuttx.bin`

---

## 三、Windows 烧录（覆盖测试界面）

1. Type-C **数据线**接开发板 **USB to UART**  
2. 设备管理器确认 COM（你们常用 **COM7**）  
3. **关掉** PuTTY / 串口脚本，避免占口  
4. 烧录时准备按 **RESET**

```powershell
cd e:\openvela\contest2026_313_bianyuanxingzhe

powershell -ExecutionPolicy Bypass -File scripts\flash_sf32.ps1 `
  -Port COM7 `
  -Firmware "VMware_share\artifacts\nuttx.bin@0x12010000"
```

或一键：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\一键烧录并测屏.ps1
```

失败可降波特率：

```powershell
& tools\sftool\sftool.exe -c SF32LB52 -p COM7 -b 115200 --compat true `
  write_flash --verify "VMware_share\artifacts\nuttx.bin@0x12010000"
```

**不要**随便整片 `erase_flash`（易伤校准区）。

---

## 四、烧完怎么确认已离开测试 UI

串口 **COM7 · 1000000**：

```text
ew help
ew boot
ew alert warn
ew screen
```

| 现象 | 含义 |
|------|------|
| 上电深蓝待机 / `ew alert` 变色 | 主程序出口正常 |
| 仍是 LVGL Demo 菜单/控件 | 还是旧镜像，或 rcS 仍有 `lvgldemo` → 重编再烧 |
| 黑屏但串口有 NSH | 屏排线/驱动问题，见 `docs/DevKit-LCD_屏幕接线与自检.md` |

## 五、临时绕过（不重编也能试）

若当前固件里已有 `ew`，串口可直接：

```text
ew boot
ew alert warn
```

若 `lvgldemo` 已占屏，效果可能被盖住；**根治仍是改 rcS + 重编烧录**。

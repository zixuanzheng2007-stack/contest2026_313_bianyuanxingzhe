## 2. 选型结论（定案）

### 2.1 推荐型号

| 项 | 定案 |
|----|------|
| 型号 | **HLK-LD2451-24G**（海凌科，后方来车/车辆状态提醒） |
| 射频架构 | 1T2R，FMCW |
| 场景匹配 | 室外侧后快速移动目标（电自/电动车/自行车），与 Varia 类骑行雷达同技术路线 |
| 预算 | 模组约 ¥40 量级，远低于大赛自购上限 |

### 2.2 明确不选用的型号

| 型号 | 为何不选 |
|------|----------|
| **LD2410 / LD2450 等「人存在」雷达** | 面向室内人体微动/静止检测，非「后方来车/车辆接近」；距离/速度/方向语义与行人防电自不匹配 |
| **77GHz 车规 BSD 后装套件** | 体积、功耗、成本不适合腰戴；安装与供电复杂 |
| **纯超声模组** | 有效距离过短（通常 1～3 m），预警窗口不足，仅可作极近补盲（非 MVP） |

### 2.3 项目有效距离目标（与模组能力区分）

| 层级 | 距离 | 说明 |
|------|------|------|
| 模组标称 | 最远约 **100 m** | 厂商手册；开阔室外、大RCS 车辆 |
| **本项目工程目标** | **15～40 m 可用** | 腰戴低安装、遮挡、城市杂波；不对标 Varia 140 m |
| 强告警建议窗口 | **TTC &lt; 3～5 s** 对应距离段 | 由端侧策略根据距离+接近速度计算，非雷达单独决定 |

## 4. 电气与接口要求

### 4.1 雷达模组供电

| 参数 | 要求 |
|------|------|
| 供电电压 | **DC 5 V ±5%** |
| 峰值电流能力 | **≥ 200 mA**（手册要求） |
| 平均工作电流 | 约 **107 mA**（手册典型） |
| 与主控关系 | 锂电池 VBAT **3.7～4.7 V**，**不能直接给 LD2451 供电**；优先用板载 5V 或升压 |

**定案：必须增加 5 V 升压模块（或带 5 V 输出的电源管理），从 VBAT/VSYS 取电。**

建议：

- 升压芯片输出 **5 V / ≥300 mA** 留裕量  
- 雷达电源经 **MOS 开关或 LDO 使能**，便于固件做间歇探测降功耗  
- 雷达 5 V 与主控 3.3 V **共地**  
- 在雷达 VCC 近端加 **10 µF + 0.1 µF** 去耦

### 4.2 通信接口

| 参数 | 要求 |
|------|------|
| 主接口 | **UART TTL 3.3 V** |
| 默认波特率 | **115200 bps** |
| 数据格式 | **8N1**（8 数据位，无校验，1 停止位） |
| 字节序 | **小端**（协议帧内多字节数值） |
| 辅助接口 | **2 × GPIO（3.3 V）** | MVP 可不接；可选作雷达「有目标」硬线告警 |
| 蓝牙 | 模组支持手机 APP 调参 | 开发阶段可用；**量产后以 UART + 端侧配置为准** |

### 4.3 DevKit-LCD 侧 UART 分配（定案建议）

DevKit-LCD openvela 默认将某一路 UART 作 **Debug 控制台**，**雷达不得占用 Debug UART**；具体脚号以 `sf32lb52_devkit_lcd` 原理图 / `bsp_pinmux.c` 为准（勿沿用黄山派 30P 脚表）。

| 功能 | 引脚 / 接口 | 说明 |
|------|-------------|------|
| 控制台 | Debug UART（板级默认） | 保持调试与 NSH；**禁止接雷达** |
| **雷达 UART（建议 UART2）** | 经 DevKit-LCD 排针引出 | SF32LB52 支持 UART 映射；**到货后冻结脚号写入接线表** |
| 参考映射（SDK 示例） | 以板级 `bsp_pinmux.c` 为准 | 避开 SD/SPI/WiFi SDIO 占用脚 |
| 震动马达 | 任意空闲 PWM/GPIO | 与 UART2、WiFi 脚不冲突即可 |
| IMU（若外挂） | I2C/SPI | 按 DevKit-LCD 空闲总线分配 |

**接线表（逻辑）**

```
LD2451 TX  ──►  MCU UART RX
LD2451 RX  ◄──  MCU UART TX
LD2451 GND ───  MCU GND
LD2451 VCC ───  5V（经升压，建议可开关）
```

**电平**：双方均为 3.3 V TTL，**无需电平转换**。

### 4.4 openvela 侧软件接口（目标）

| 项 | 要求 |
|----|------|
| 设备节点 | 新增 `/dev/ttyS1` 或等价 UART2 节点（以板级配置为准） |
| 驱动 | 使用 NuttX `sf32lb_uart`；雷达解析在用户态 `radar` 模块 |
| 读取方式 | 推荐 **DMA + IDLE 中断** 收帧（SiFli SDK UART 示例支持） |
| 解析频率 | 有目标时约 **100 ms/帧**；无目标约 **1 s/帧**（模组行为） |
| 端侧延迟 | 从 UART 收满一帧到策略引擎输入 **&lt; 50 ms**（不含 Agent Tool 执行） |

## 5. 数据协议与输出字段

### 5.1 配置命令帧格式

| 字段 | 值 |
|------|-----|
| 帧头 | `FD FC FB FA` |
| 帧尾 | `04 03 02 01`（配置通道） |
| 流程 | **使能配置 `0x00FF` → 发命令 → 收 ACK → 结束配置 `0x00FE`** |
| ACK | 2 字节状态：**0=成功，1=失败** |

### 5.2 检测数据帧格式（上报）

| 字段 | 值 |
|------|-----|
| 帧头 | `F4 F3 F2 F1` |
| 帧尾 | `F8 F7 F6 F5` |
| 最大目标数 | **5** |

**每目标字段（与边缘行者策略相关）**

| 字段 | 长度 | 解析 |
|------|------|------|
| 报警信息 | 1 B | `0x01`=有目标靠近，`0x00`=无靠近 |
| 角度 | 1 B | 实际角度 = **上报值 − 0x80**（度） |
| 距离 | 1 B | **0～100 m** |
| 速度方向 | 1 B | `0x01`=靠近，`0x00`=远离 |
| 速度 | 1 B | **0～120 km/h** |
| 信噪比 SNR | 1 B | **0～255** |

**端侧必须使用的量**：距离、速度、速度方向、角度、SNR、是否靠近。  
**TTC 计算**（端侧策略，非雷达直接输出）：

```
若 speed_kmh > 0 且方向=靠近：
  speed_mps = speed_kmh / 3.6
  TTC_s ≈ distance_m / speed_mps
否则：
  TTC 无效，仅距离门限
```

## 6. 可配置参数与推荐初值

以下参数均可通过串口写入，**掉电保存**，重启后生效。开发阶段可用海凌科 **HLKRadarTool** 手机 APP（蓝牙）辅助，**量产与路测以 UART 配置为准**。

### 6.1 目标检测参数（命令字 `0x0002`，4 字节）

| 子参数 | 范围 | **边缘行者推荐初值** | 说明 |
|--------|------|----------------------|------|
| 最远检测距离 | 10～100 m（协议最小 0x0A） | **40 m（0x28）** | 对齐项目 15～40 m 目标；路测可改 30～50 m |
| 运动方向 | 00 远离 / 01 靠近 / 02 双向 | **01 只检测靠近** | 行人只关心来车，忽略远离目标减噪 |
| 最小运动速度 | 0～120 km/h | **5 km/h（0x05）** | 过滤慢速行人/推车；路口可配合 IMU 降敏 |
| 无目标延迟 | 0～255 s | **2 s（0x02）** | 目标消失后保持告警状态时长；防闪烁 |

### 6.2 灵敏度参数（命令字 `0x0003`，4 字节）

| 子参数 | 范围 | **推荐初值** | 说明 |
|--------|------|--------------|------|
| 累积有效触发次数 | 1～10 | **2** | 连续 2 次才上报，抑单次杂波 |
| 信噪比阈值 | 默认 4；可调 3～8 | **4（默认）** | 越低越灵敏、误报越多；**非必要不改** |
| 扩展参数 | — | `0x00 0x00` | 保持默认 |

### 6.3 串口波特率（命令字 `0x00A1`）

| 项 | 定案 |
|----|------|
| 出厂默认 | **115200（索引 0x0005）** |
| 是否修改 | **MVP 不改**；若改须重启模组且同步修改 openvela UART 配置 |

### 6.4 查询与版本

| 命令字 | 用途 |
|--------|------|
| `0x0013` | 读取当前灵敏度配置 |
| `0x00A0` | 读取固件版本（类型 0x2451） |

## 7. 调参方法与流程

### 7.1 三阶段调参

```
阶段 A：台架/走廊静态标定（实验室）
  → 距离、速度、方向、灵敏度

阶段 B：穿戴静态标定（人站立/慢走）
  → 朝向、扇区、最小速度、触发次数

阶段 C：路测迭代（辅路 / 路口 / 拥堵）
  → IMU×导航降敏 + 雷达参数联合微调
```

### 7.2 配置操作步骤（UART）

1. 上电，等待模组 **≥ 1 s** 稳定  
2. 发送 **使能配置** `0x00FF`，等待 ACK=0  
3. 发送 **0x0002** 目标检测参数 / **0x0003** 灵敏度参数  
4. 发送 **结束配置** `0x00FE`，等待 ACK=0  
5. **重启模组或重新上电**（波特率类命令必须重启）  
6. 记录配置到 `radar_profile.json` 或 Skill 可读配置文件，便于复现

### 7.3 场景化调参表（端侧 + 雷达联合）

| 场景 | 雷达侧建议 | 端侧策略（IMU/导航） |
|------|------------|----------------------|
| 直线辅路 | 距离 40 m，靠近，最小速度 5 km/h | 正常灵敏度 |
| 路口 / 转弯 | 最小速度 **8～10 km/h** 或触发次数 **3** | IMU 识别转弯 → **降敏** |
| 等灯 / 静止 | 不变 | IMU 静止 → **降敏或静默** |
| 近路口（导航 BLE） | 距离暂收 **25～30 m** | 导航标签 `dist_to_crossing` 近 → **降敏** |
| 听障 profile | 雷达不变 | 震动等级提高，冷却时间缩短 |
| 视障 profile | 雷达不变 | 耳标 + 腰震；雷达仍主探 |

**原则**：导航与 Agent **只调灵敏度档位**，不直接发「震动」；冲突时 **信 IMU**。

### 7.4 告警门限（端侧策略，非雷达寄存器）

| 等级 | 条件（示例） | 执行 |
|------|--------------|------|
| 无 | 无靠近目标 / TTC 过大 | 不震动 |
| 软 | 距离 &lt; 25 m 且靠近，TTC 5～3 s | 短震 1 次 |
| 强 | 距离 &lt; 15 m 或 TTC &lt; 3 s | 连续震 2～3 次 |
| 紧急 | 距离 &lt; 8 m 或 TTC &lt; 1.5 s | 强震 + 日志 |

以上门限在 `policy_engine` 实现，**不由 LLM 决定**；Agent Tool 仅执行已判决等级。

### 7.5 常见问题与调参方向

| 现象 | 可能原因 | 调整 |
|------|----------|------|
| 直线漏报 | 距离设太短 / 最小速度太高 | 距离 ↑ 至 40～50 m；速度降至 3～5 km/h |
| 路口狂震 | 横向目标过多 | 端侧 IMU 降敏 + 最小速度 ↑ + 触发次数 ↑ |
| 路边停车误报 | 静止车被当移动 | 确认方向=**只靠近**；端侧过滤「速度≈0」 |
| 行人擦过误报 | 扇区过宽 | 端侧角度过滤（仅 ±60°～±120° 侧后扇区） |
| 数据卡顿 | UART 阻塞 | 启用 DMA；独立线程解析 |
| 完全无数据 | 5 V 不足 / TX-RX 反接 | 测 5 V 电流；交换 UART 线 |

## 8. 与 DevKit-LCD 系统的集成约束

### 8.1 功耗与续航

| 项 | 估算 |
|----|------|
| DevKit-LCD + WiFi（原型） | 较高；量产无屏腰扣可再降耗 |
| LD2451 常开 | ~107 mA @ 5 V ≈ **0.5 W** |
| 450 mAh 电池 | 若雷达常开，**续航仅数小时级** |

**定案策略**：

1. **间歇探测**：步行时 100 ms 级工作占空比（如 0.3～0.5）；静止 IMU 判定后 **雷达休眠或降频**  
2. **雷达电源开关**：GPIO 控制 5 V 使能  
3. 演示长时间路测可用外接电源兜底

### 8.2 与板载 IMU 协同

| 传感器 | 接口 | 用途 |
|--------|------|------|
| LSM6DS3TR-C（板载） | I2C1 | 走/停/转弯识别 → 雷达灵敏度档位 |
| LD2451 | UART2 | 距离、速度、角度、靠近判定 |

### 8.3 与 ai_agent 边界

| 模块 | 职责 |
|------|------|
| `radar` + `policy` | 解析 UART、算 TTC、输出 `alert_level` |
| `ai_agent` | 阈值越限 **主动** 触发，Tool 执行 `haptic_alert` |
| MiMo 云端 | 仅解释配置、简报；**不参与雷达调参的实时闭环** |
| Skill `approach-guard` | 保存 profile 与门限表；CLI/语音改 **档位**，不改安全环硬编码上限 |

## 附录 A：配置命令示例（十六进制，仅供开发参考）

**使能配置**

```
FD FC FB FA 04 00 FF 00 01 00 04 03 02 01
```

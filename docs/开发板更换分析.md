# 开发板更换分析与定案（响应赛方审核）

> 依据：参赛资源包状态查询 · 开发板审核建议  
> 仓库：`contest2026_313_bianyuanxingzhe`  
> 审核原文：**「wifi 需拓展，建议使用 lcd 开发板」**  
> 版本：1.0 · 2026-08-05

---

## 1. 审核意见解读

| 要点 | 含义 |
|------|------|
| wifi 需拓展 | 当前申报的 **黄山派** 以双模蓝牙为主，外设扩展口紧张，**不便稳定扩展 SDIO WiFi**；云端 Agent / MiMo / 联网演示能力偏弱，审核要求补齐联网拓展能力 |
| 建议使用 lcd 开发板 | 赛方清单中的 **SF32LB52 LCD（DevKit-LCD）**：同芯片族、接口更全，官方支持 **SDIO WiFi 选项**，并带 LCD 便于调试与状态展示 |

**不是**要求改成 ESP32-S3 EYE 或大算力边缘板；而是在思澈 SF32LB52 路线内，从「穿戴原型黄山派」换成「可扩展的 LCD 开发板」。

---

## 2. 黄山派 vs SF32LB52 LCD

| 维度 | 黄山派（原申报） | **SF32LB52 LCD（新定案）** |
|------|------------------|----------------------------|
| 芯片 | SF32LB52 | **同族 SF32LB52**（软件可大量复用） |
| 无线 | 双模蓝牙为主 | 蓝牙 + **可扩展 SDIO WiFi**（审核点） |
| 扩展 | 30P，手表形态优先，SDIO/WiFi 受限 | **SDIO、USB、TF、丰富排针**，外设更好挂 |
| 显示 | 1.85" AMOLED（一体穿戴） | **专用 LCD 接口**，利于调试 UI / 告警等级显示 |
| 形态 | 最贴「手表/帽圈」 | 更贴 **腰包主脑 + 外挂雷达**（竞赛原型可接受） |
| openvela | `lckfb_huangshan_pi` | `sf32lb52_devkit_lcd`（大赛分支已有） |
| 雷达接入 | UART + 5V 升压 | **不变**：仍 UART TTL 3.3V + LD2451 |

---

## 3. 定案

| 项 | 内容 |
|----|------|
| **新主控** | **SF32LB52 LCD（DevKit-LCD）** |
| **雷达** | 仍为 **HLK-LD2451**（不改） |
| **形态叙事** | 腰包/腰侧主控盒（LCD 可显告警档位/调试信息）+ 环状固定雷达；量产可再缩成无屏腰扣 |
| **联网** | 开发期用 **SDIO WiFi 模组扩展**（或板载方案按到货模组版本 -A 等），服务 ai_agent / MiMo；**告警安全环仍断网可用** |
| **原黄山派** | 降为形态预研/低功耗参考，**不再作为申领与文档主选** |

---

## 4. 对工程的影响

| 模块 | 影响 |
|------|------|
| 雷达接线 | 逻辑不变（UART2 + 5V + 共地）；**脚位按 DevKit-LCD 原理图重出接线表** |
| 感知/策略代码 | 基本可迁；改板级 UART/PWM pinmux |
| ai_agent | 更易联网演示；Skill/Tool 逻辑不变 |
| 硬件工作量 | +WiFi 模组选型与天线；+LCD 简单状态页（可选 MVP） |
| 初期安排 | 部分一改为「LCD 板到货 + WiFi 冒烟 + 雷达接线」 |

---

## 5. 建议立刻做的动作

1. 资源包 / 申领侧：按审核意见改为 **SF32LCD / SF32LB52 LCD 开发板**（以官网选项原文为准）。  
2. 组内冻结：主控名称统一为 **SF32LB52 LCD**。  
3. 拉取 openvela 板级：`boards/sf32lb52/sf32lb52_devkit_lcd`。  
4. 确认到货模组是否支持 **SDIO WiFi（-A）**；不支持则外挂 USB/SDIO WiFi 方案写进 BOM。  
5. 文档与 Word 包已按本定案迭代（见同目录其它 md）。

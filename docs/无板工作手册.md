# 边缘行者 · 无板工作手册

> 项目：边缘行者（行人侧后电自/电动车接近预警）  
> 主控（到货后）：SF32LB52 LCD / DevKit-LCD · 雷达：HLK-LD2451  
> 无板工程：`edge-walker/`  
> 专属仓：`contest2026_313_bianyuanxingzhe` · 分支：`dev-ai-contest-2026`  
> 版本：1.0 · 2026-08-06

---

## 1. 文档目的

本手册把**开发板未到货阶段**的工作独立成册，供组内按手册从零开工。内容包括：

1. 无板工作拆成 **A（感知）/ B（Agent）** 两份并行  
2. **从零准备环境**（Windows 主机工程 + Ubuntu/VMware 全量 openvela）  
3. 跑通演示与单测、任务清单、板上迁移对照、合规红线  

**板到后不做本手册范围内的替代**：真机烧录、UART2/PWM/WiFi 冒烟仍归硬件与部分二/三正式联调。

---

## 2. 无板能做什么、不能做什么

| 能做 | 不能做（等板/物料） |
|------|---------------------|
| 假雷达帧 → 协议解析 → TTC/告警档 | 烧录 `sf32lb52_devkit_lcd` |
| 单测与主机演示 | 真 UART2 / PWM 震动联调 |
| Agent 事件桥接 mock + Skill 草稿 | DevKit-LCD 真机 WiFi / LCD 告警页 |
| Ubuntu goldfish 跑 ai_agent | 走廊接近实测 |
| USB-TTL 先验 LD2451 模组（可选） | 以模拟器录像代替赛题真机验收 |

主路径：

```text
假雷达帧 → protocol 解析 → policy(alert_level) → AgentBridge(主动 + haptic_alert)
```

## 3. 无板工作拆分（两份并行）

工程目录统一在 `edge-walker/`，职责按模块切开，**不要混成一个 backlog**。

### 3.1 无板 A · 感知安全环（主机）

| 项 | 内容 |
|----|------|
| 对应正式阶段 | 初期安排「部分二 · 感知安全环」 |
| 一句话 | 假雷达帧跑通「解析 → 过滤 → TTC → alert_level」，单测可复现 |
| 主目录 | `protocol.py` · `policy.py` · `simulator.py` · `tests/` |
| 不负责 | LLM、Skill 话术、goldfish、真机 UART/PWM |

| 序号 | 任务 | 状态 | 完成标准 |
|------|------|------|----------|
| A1 | LD2451 帧编解码 / 流式拆包 | 已完成 | pytest 编解码与分包用例通过 |
| A2 | 过滤（只靠近 / 最小速度 / SNR） | 已完成 | 远离、慢目标不报警 |
| A3 | 粗 TTC → NONE/SOFT/STRONG/EMERGENCY | 已完成 | 近距可升到 EMERGENCY |
| A4 | 接近场景假数据 + run_demo | 已完成 | `python scripts/run_demo.py` 可出档位 |
| A5 | 补场景：多目标、遮挡抖动、门限边界 | 待做 | 单测覆盖边界；误报用例可复现 |
| A6 | 冻结告警接口 1 页（供无板 B） | 待做 | 枚举名与 payload 字段不再改 |
| A7 | （可选）USB-TTL 真模组读帧 | 待做 | PC 上可见真目标，仍本地判决 |

**无板 A 出口**：主机上假（或真模组）数据 → 档位正确；接口页交给无板 B。

### 3.2 无板 B · Agent 与赛题（主机 + 模拟器）

| 项 | 内容 |
|----|------|
| 对应正式阶段 | 初期安排「部分三 · Agent 与赛题」 |
| 一句话 | 消费告警事件，跑通「主动触发 → Tool」；Skill 可演示；上 goldfish |
| 主目录 | `agent_bridge.py` · `skills/approach-guard/` |
| 并行环境 | Ubuntu 22.04（可用 VMware）编 openvela goldfish，跑 ai_agent |
| 不负责 | TTC 判决实现、改 policy 门槛 |

| 序号 | 任务 | 状态 | 完成标准 |
|------|------|------|----------|
| B1 | 主机 AgentBridge：事件 → 主动 → haptic_alert（日志） | 已完成 | 单测通过 |
| B2 | Skill 草稿 approach-guard | 已完成 | 写明不参与判决 |
| B3 | Demo 分镜 + 合规自检清单 | 待做 | 断网震 / 联网主动各写清一步 |
| B4 | 装 Ubuntu + 拉 openvela + 编 goldfish | 待做 | 模拟器可进系统 |
| B5 | goldfish 跑通 ai_agent 最小示例 | 待做 | CLI 可用 |
| B6 | 假事件注入 → 主动 → Tool（模拟器侧） | 待做 | 与无板 A 字段对齐 |
| B7 | Tool / Skill 板上迁移 checklist | 待做 | 1 页说明 |

**无板 B 出口**：主机 mock 可讲清；模拟器至少一次「主动 + Tool」；Skill ≥1。

### 3.3 协作约定

| 规则 | 说明 |
|------|------|
| 接口归属 | A 冻结 `alert_level` / `approach_threshold_exceeded` / payload；B 只消费不改语义 |
| 合码 | A 动 protocol/policy/simulator；B 动 agent_bridge/skills 与 Ubuntu 侧 |
| 日同步 | A 单测/接口、B 模拟器阻塞、硬件到货 |
| 板未到验收 | A：假雷达走出正确档；B：假事件→主动→Tool |

告警接口（冻结前勿随意改名）：

```text
alert_level: NONE | SOFT | STRONG | EMERGENCY
event: approach_threshold_exceeded
payload: range_m, speed, azimuth, ttc_s, timestamp
```

## 4. 从零准备环境（总览）

无板阶段需要 **两套环境**，可分人负责：

| 环境 | 谁用 | 操作系统 | 用途 |
|------|------|----------|------|
| **环境一** | 无板 A（及 B 的主机 mock） | **Windows 10/11** 即可 | 跑 `edge-walker`、写协议/策略、pytest |
| **环境二** | 无板 B 主责 | **Ubuntu 22.04**（物理机或 VMware） | `repo sync`、编 goldfish、跑 ai_agent |

不要用 **WSL / Docker** 当 openvela 编译环境（官方不支持）。VMware 可用，属风险自担（官方只承诺原生 Ubuntu）。

建议配置：

| 项 | 环境一（Windows） | 环境二（Ubuntu / 虚拟机） |
|----|-------------------|---------------------------|
| 内存 | ≥8 GB 可用 | 建议分给虚拟机 **≥16 GB** |
| 磁盘 | ≥5 GB（本工程很小） | **≥80 GB**（源码+编译） |
| 网络 | 能访问 GitHub / pip | 能访问 GitHub 或 Gitee 镜像 |
| 其它 | Python 3.10+、Git、Cursor | VT-x + 嵌套虚拟化（跑模拟器时） |

## 5. 环境一：Windows 从零到跑通 edge-walker

按顺序做；任一步失败先解决再往下。

### 5.1 安装 Git

1. 打开：https://git-scm.com/download/win  
2. 安装时保持默认即可（建议勾选「Add to PATH」）  
3. 新开 PowerShell 验证：

```powershell
git --version
```

### 5.2 安装 Python 3.10+

1. 打开：https://www.python.org/downloads/  
2. 安装时勾选 **Add python.exe to PATH**  
3. 验证：

```powershell
python --version
python -m pip --version
```

若 `python` 找不到，可试 `py -3 --version`。

### 5.3 安装 Cursor（或 VS Code）并打开专属仓

工作区根目录必须是专属仓，不要用更外层的 `e:\openvela`：

```text
e:\openvela\contest2026_313_bianyuanxingzhe
```

### 5.4 获取仓库代码

**方式 A：本机已有仓（当前常见）**

```powershell
cd e:\openvela\contest2026_313_bianyuanxingzhe
git status
git remote -v
```

应能看到 `upstream` 指向组委会仓；`origin` 一般为你的 Fork。

**方式 B：从零 clone**

```powershell
cd e:\openvela
git clone https://github.com/open-vela/contest2026_313_bianyuanxingzhe.git
cd contest2026_313_bianyuanxingzhe
git checkout dev-ai-contest-2026
```

推送代码前请先 **Fork** 到自己账号，再添加 `origin`（组委会仓有分支保护，一般不能直接 push）：

```powershell
git remote add origin https://github.com/<你的用户名>/contest2026_313_bianyuanxingzhe.git
```

### 5.5 安装 edge-walker 依赖并跑演示

```powershell
cd e:\openvela\contest2026_313_bianyuanxingzhe\edge-walker
python -m pip install -e ".[dev]"
python -m pytest -q
python scripts\run_demo.py
python scripts\run_demo.py --hex
```

预期：

- `pytest` 显示 **5 passed**（或后续增测后全部通过）  
- `run_demo.py` 打印接近过程中的告警档与 `[PROACTIVE]` / `[TOOL] haptic_alert` 日志  

### 5.6 目录对照（环境一日常改哪里）

```text
edge-walker/
  src/edge_walker/
    protocol.py      # 无板 A：LD2451 帧
    policy.py        # 无板 A：过滤 + TTC + 档位
    simulator.py     # 无板 A：假接近场景
    agent_bridge.py  # 无板 B：主动 + Tool mock
    models.py        # 共享数据结构
  skills/approach-guard/SKILL.md   # 无板 B：Skill 草稿
  scripts/run_demo.py
  tests/
  docs/无板开发说明.md
```

### 5.7 环境一常见问题

| 现象 | 处理 |
|------|------|
| `python` 不是内部命令 | 重装 Python 并勾选 PATH；或用 `py -3` |
| `pip install` 很慢 | 换清华源：`python -m pip install -e ".[dev]" -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| pytest 找不到包 | 确认在 `edge-walker` 目录执行了 `pip install -e ".[dev]"` |
| 演示无输出 | 先 `pytest`；再检查是否在正确目录 |

## 6. 环境二：Ubuntu（VMware 可）从零到 goldfish

无板 B 用于练 **openvela + ai_agent**。以下按「全新机器 / 新虚拟机」书写。

### 6.1 是否用 VMware

| 环境 | 官方态度 | 建议 |
|------|----------|------|
| 物理机 Ubuntu 22.04 | 正式支持 | 最稳 |
| **VMware 装 Ubuntu 22.04** | 未写禁止，也不背书 | **可做编译；模拟器可能要折腾** |
| WSL / Docker | **不支持** | 不要用作主环境 |

VMware 推荐设置：

1. 客户机选 **Ubuntu 22.04**（勿首选 24.04）  
2. 内存 **≥16 GB** 分给虚拟机；磁盘 **≥80 GB**  
3. 开启 **VT-x/AMD-V**；跑 `emulator.sh` 时开启 **嵌套虚拟化**  
4. 安装 `open-vm-tools` 便于共享文件夹与分辨率  

### 6.2 安装 Ubuntu 后：系统依赖

打开终端：

```bash
sudo apt update
sudo apt install -y git curl cmake python3 libc++abi-dev build-essential ninja-build gcc g++
```

安装并初始化 **Git LFS**（官方要求，否则大文件损坏）：

```bash
curl -s https://packagecloud.io/install/repositories/github/git-lfs/script.deb.sh | sudo bash
sudo apt-get install -y git-lfs
git lfs install
```

配置 Git 用户（提交用）：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

### 6.3 安装 repo 工具

```bash
curl -sSL "https://storage.googleapis.com/git-repo-downloads/repo" > repo
chmod +x repo
sudo mv repo /usr/local/bin
repo --version
```

若 Google 存储访问困难，可改用清华镜像上的 git-repo（见下一步 `repo init` 的 `--repo-url`）。

### 6.4 拉取完整工程（大赛专属清单）

**推荐：用队伍专属仓的 manifest**（与组委会 README 一致），同步后专属仓与 openvela 全量在同一工作区：

```bash
mkdir -p ~/openvela && cd ~/openvela
repo init -u https://github.com/open-vela/contest2026_313_bianyuanxingzhe \
  -b dev-ai-contest-2026 -m contest2026_313_bianyuanxingzhe.xml \
  --repo-url=https://mirrors.tuna.tsinghua.edu.cn/git/git-repo/ --git-lfs
repo sync -c -j8
```

同步后：

- 专属仓：`~/openvela/contest2026_313_bianyuanxingzhe/`  
- 全量源码：同级的 `nuttx/`、`apps/`、`packages/`、`vendor/` 等  
- 构建在 **openvela 工作区根目录**（`~/openvela`），不是只在专属仓里  

若官方通用清单更熟，也可按 [快速入门（Ubuntu）](https://github.com/open-vela/docs/blob/dev-ai-contest-2026/zh-cn/quickstart/openvela_ubuntu_quick_start.md) 用 `manifests.git` + `openvela.xml`；**参赛提交仍以专属仓为准**。网络不稳时可换 Gitee / GitCode 源（见官方文档选项 B/C）。

首次 `repo sync` 耗时长，中断后可重复执行增量同步。

### 6.5 把 Windows 上的无板代码同步进 Ubuntu

任选其一：

1. **Git**：在 Windows 推送到你的 Fork，Ubuntu 进入专属仓 `git pull`  
2. **共享文件夹 / scp**：拷贝 `docs/`、`edge-walker/`  

保持专属仓目录结构，便于以后 linkfile / 提交。

### 6.6 编译 goldfish 模拟器固件

在 openvela 根目录（`~/openvela`）：

```bash
cd ~/openvela

# 可选：打开 menuconfig，启用 Packages → Vela AI Agent
./build.sh vendor/openvela/boards/vela/configs/goldfish-arm64-v8a-ap/ --cmake menuconfig

# 编译（内存紧张改为 -j2）
./build.sh vendor/openvela/boards/vela/configs/goldfish-arm64-v8a-ap/ --cmake -j$(nproc)
```

若要按官方 ai_agent 示例 **覆盖 defconfig 后重编**：

```bash
cp packages/ai_agent/defconfigs/goldfish-arm64-v8a-ap/goldfish-arm64-v8a-ap_defconfig \
   vendor/openvela/boards/vela/configs/goldfish-arm64-v8a-ap/defconfig
rm -rf cmake_out/vela_goldfish-arm64-v8a-ap
./build.sh vendor/openvela/boards/vela/configs/goldfish-arm64-v8a-ap --cmake -j8
```

产物目录示例：`cmake_out/vela_goldfish-arm64-v8a-ap/`。

### 6.7 启动模拟器

```bash
cd ~/openvela
./emulator.sh cmake_out/vela_goldfish-arm64-v8a-ap/
```

看到类似 `goldfish-armv8a-ap>` / `nsh>` 提示符即成功。

goldfish 默认 NAT 网络（如 eth0 `10.0.2.15`），**一般无需 WiFi 配网**即可测云端 LLM。

### 6.8 在模拟器里跑通 ai_agent 最小对话

```text
nsh> ai_agent
```

进入 `vela>` 后：

```text
vela> router_set mimo <你的_api_key>
vela> router_status
vela> ask 你好，请介绍一下你自己
```

| 服务 | 申请地址 | 说明 |
|------|----------|------|
| 小米 MiMo | https://mimo.mi.com/ | 优先推荐 |
| DeepSeek | https://platform.deepseek.com/ | 备选 |

更细的 Tool / Skill / 通道配置见官方：  
[ai_agent 应用开发上手指南](https://github.com/open-vela/docs/blob/dev-ai-contest-2026/zh-cn/contest_2026/ai_hardware/ai_agent_quickstart.md)

### 6.9 环境二常见问题

| 现象 | 处理 |
|------|------|
| `cc1plus: out of memory` | `./build.sh ... -j2`；加大虚拟机内存 |
| 模拟器起不来 / 黑屏 | 开嵌套虚拟化；先保证编译成功再折腾显示 |
| `cmake: command not found` | `sudo apt install cmake ninja-build` |
| defconfig 改了不生效 | `rm -rf cmake_out/` 后重配重编 |
| repo sync 失败 | 换镜像源；重复 `repo sync -c -j8` |
| LFS 文件只有几 KB | 确认执行过 `git lfs install` 后重新 sync |

## 8. 板上迁移对照（无板做完以后）

| 主机模块（edge-walker） | 板到后 |
|-------------------------|--------|
| simulator / 假帧 | UART2 读 LD2451 真帧 |
| protocol | 迁 C/C++ `radar_ld2451`（字段语义保持） |
| policy | 迁端侧 `policy` 任务 |
| agent_bridge | openvela `ai_agent` Tool + Skill |
| skills/approach-guard | 拷到板上 skills 目录（路径以赛题为准） |

电脑连板：Type-C **数据线** 插开发板 **USB to UART** 口（A-to-C / C-to-C 均可）；Windows 需 CH34x 驱动。雷达另接 UART2 + 5V，不占用 Debug 串口。

## 9. 合规红线（无板阶段也要遵守）

| 允许 | 禁止 |
|------|------|
| 本地 `policy` 判等级，Tool 只执行 | LLM 决定震不震 |
| Skill 说明/改灵敏度档位（配置） | 绕过安全环强制告警 |
| 主机 mock 用日志代替震动 | 用「只有聊天」交差 |

断网安全环不依赖网络；Agent 联网演示是加分项，不是告警前提。

# 阶段一：接口与规则冻结

> 基线：`dev-ai-contest-2026` @ `8a16266`
> 日期：2026-10-19
> 负责人：角色 B（产品交付）

## 1. 阶段目标

先把“谁能改什么、事件长什么样、日志怎样算通过”定下来，再并行开发。

阶段一完成后必须满足：

- fake 事件和真实雷达事件进入同一个 B 侧分发入口。
- 每个事件都有唯一的 `event_id` 和明确的 `source`。
- `event_id/source` 穿越 Agent、Tool、IPC、告警输出和 LCD 日志。
- A 的距离、TTC、告警门限和等级计算不被 B 修改。
- 10 次事件可以在同一份记录表中逐项核对。

## 2. 责任边界

| 内容 | 负责人 | 规则 |
|------|--------|------|
| `level / range_m / speed_kmh / ttc_s / reason` | A | B 只消费，不重算、不改写 |
| `event_id / source` | B | 由 B 在事件入口生成并全程透传 |
| Agent Tool 参数与日志格式 | B | A 可审查，B 最终确认 |
| LCD、蜂鸣、IPC、演示入口 | B | 必须使用统一出口 |

`ew_decision_t` 保持 A 的安全语义不变；B 的追踪信息放在事件信封中。

## 3. 冻结字段

```text
event_id    string   格式：evt-<source-tag>-<time>-<seq>
source      enum     radar | fake | manual | serial | agent
level       enum     NONE | SOFT | STRONG | EMERGENCY
range_m     float    来自 A
speed_kmh   float    来自 A
ttc_s       float    来自 A，<0 表示无效
reason      string   来自 A 或测试入口
```

约束：

- `event_id` 在一个启动周期内不可重复。
- `source` 只表示事件从哪里进入，不表示新的安全等级。
- `level/range_m/ttc_s` 不允许在 Tool 或 IPC 层重新计算。
- `NONE` 也是事件，必须记录“解除告警”的完整链路。

## 4. 唯一事件入口

所有告警来源统一调用：

```c
ew_agent_emit_decision(const ew_decision_t *decision,
                       ew_event_source_t source);
```

调用位置：

| 来源 | 入口 |
|------|------|
| 真实雷达主循环 | `ew_main.c` / `alert_lcd.c` |
| NSH `ew fake` | `ew_main.c` |
| NSH `ew alert` | `ew_main.c` |
| PC 串口 `@fake` / `@alert` | `ew_serial_ctl.c` |
| ai_agent 外部 Tool | `tool_approach_alert_execute()` |

统一链路：

```text
decision
  -> ew_agent_emit_decision
  -> [ew_event] 记录 event_id/source
  -> [ew_agent] 主动调用 approach_alert
  -> [ai_agent] Tool 接收并保留 event_id/source
  -> [ew_ipc] 跨进程排队（如适用）
  -> [alert_output] 实际出口
  -> [alert_lcd] 屏幕执行
```

## 5. Tool JSON 冻结

内部调用：

```json
{
  "event_id": "evt-rad-67f1a2b4-0001",
  "source": "radar",
  "level": "strong",
  "reason": "R 12.0m approaching"
}
```

外部 Agent 或人工调试可以省略 `event_id/source`，Tool 会生成
`evt-agt-*`，来源回退为 `agent`。任何情况下 Tool 都不得修改 `level`。

## 6. 日志验收格式

一次事件至少应出现以下关键行：

```text
[ew_event] event_id=evt-rad-... source=radar level=STRONG range=12.0m
[ew_agent] proactive approach_alert event_id=evt-rad-... source=radar
[ai_agent] tool approach_alert event_id=evt-rad-... source=radar level=STRONG
[alert_output] event_id=evt-rad-... source=radar level=STRONG reason=...
[alert_lcd] executor event_id=evt-rad-... source=radar level=STRONG
```

跨进程路径必须额外出现：

```text
[ew_ipc] queued event_id=evt-rad-... source=radar level=STRONG
[alert_lcd] ipc event_id=evt-rad-... source=radar level=STRONG
```

验收时以同一个 `event_id` 贯穿为准，不以“看到了某一行日志”代替完整链路。

## 8. 板端验收

阶段一 G1 通过条件：

- `ew fake 10 2` 和真实雷达事件都出现 `[ew_event]`。
- 10 次事件都能用同一个 `event_id` 找到 Tool 和告警出口日志。

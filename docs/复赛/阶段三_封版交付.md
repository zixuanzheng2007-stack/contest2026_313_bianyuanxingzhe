## 1. 本阶段目标

按复赛分工第三周完成可回退交付，而不是继续增加功能：

- 把主固件、可选独立 Agent 固件、源码输入、工具、回退镜像和说明装进同一版本包。
- 为每个文件生成 SHA256，禁止覆盖旧版本。
- 烧录前离线核对 ARM ELF、bin、配置、入口和 `0x12010000` 加载地址。
- 提供连续三次演示的记录脚本和人工观察表。
- 主机、烧录、屏幕、蜂鸣、真实雷达和长稳分别记录，不把主机通过写成实板通过。

本阶段没有修改距离、TTC、门限或告警等级，也没有覆盖阶段二的联网故障和
对话隔离实现。

## 3. 组长编译和封版

前提：openvela SDK、ARM 工具链和板级配置已经可用。`ROLLBACK_BIN` 必须是
此前确认可工作的主固件，脚本不会猜一个回退版本。

```bash
cd ~/openvela/contest2026_313_bianyuanxingzhe
export ROLLBACK_BIN=/path/to/known_good/nuttx.bin
export VERSION=ew-final-20261027
bash scripts/guest/build_stage3_release.sh
```

只封主固件时：

```bash
WITH_AGENT=0 ROLLBACK_BIN=/path/to/known_good/nuttx.bin \
  VERSION=ew-final-main-20261027 \
  bash scripts/guest/build_stage3_release.sh
```

有手机 APK 时再加：

```bash
APK=/path/to/edge-walker-companion-debug.apk \
ROLLBACK_BIN=/path/to/known_good/nuttx.bin \
VERSION=ew-final-full-20261027 \
bash scripts/guest/build_stage3_release.sh
```

默认产物：

```text
output/stage3/<version>/
output/stage3/<version>.zip
output/stage3/<version>.zip.sha256
```

脚本会在发布前自动再校验一次便携 ZIP。旧版本已存在时拒绝覆盖。

## 4. 单独校验和烧录

```bash
python3 scripts/host/stage3_delivery.py verify \
  --package output/stage3/<version>.zip
```

Windows 烧录：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/host/flash_sf32.ps1 `
  -Port COM7 `
  -Firmware "output/stage3/<version>/firmware/main/nuttx.bin@0x12010000"
```

不要整片擦除，不使用 ELF 入口地址，不把独立 Agent 镜像和主镜像同时写到一个分区。

## 5. 连续三次演示

烧录后，关闭串口占用，执行：

```powershell
python scripts/host/stage3_demo_acceptance.py --port COM7 --runs 3
```

每一轮自动切换 `WARN -> CHAT -> WIFI -> WARN`，触发 fake 决策、Agent、Tool、
`alert_output` 和只读快照。软件日志必须出现至少三条完整事件链：

```text
decision -> agent -> tool -> alert_output -> complete
```

脚本的 `SOFTWARE_CHAIN=PASS` 只说明串口软件链完整。屏幕颜色、蜂鸣、真实雷达
触发与三次现场演示仍需人工观察，并记录到
`docs/复赛/阶段三_连续三次演示记录.csv`。

已有串口日志可离线复查：

```powershell
python scripts/host/stage3_demo_acceptance.py `
  --replay VMware_share/artifacts/stage3_three_demos_xxx.txt `
  --runs 3
```

## 6. 回退

1. 先执行 `verify --package` 核对封版包。
2. 开发板异常时烧 `rollback/nuttx.bin@0x12010000`。
3. 源码问题在 GitHub 使用 Revert 或关闭 PR，不强推主分支。
4. 回退后重新跑 `@status`、`@snapshot`、`@fake 1.0 40.0`，确认本地告警恢复。

## 2026-10-28 审核修正约束

旧命令示例只说明参数用途。正式运行前必须使用私有隔离 SDK：
`ISOLATION_MANIFEST` 指向隔离构建输出的 `isolation.json`，其中 private_workspace
须与 OPENVELA 一致，source_tree_sha256 须与 CONTEST 当前源码一致。
没有该证据时 build_stage3_release.sh 会拒绝构建共享 SDK。
现有 build_ew_isolated.sh 负责隔离/配置脱敏，并为成功构建记录源码收据；
其本机路径和历史版本默认值必须由本轮实际输入覆盖，不能照抄旧摘要。

直接 seal 时，主固件和 Agent 构建目录均须包含 source_receipt.json；
该收据在构建前确定输入摘要，构建成功且源码未变后记录，并绑定 ELF、bin 和
.config 的实际摘要。缺失或过期收据、非空敏感配置均拒绝发布，不能事后伪造
摘要或仅删除交付副本的密钥字段。固件内已编译的秘密须经脱敏重新构建排除。

目录与 ZIP 采用相同的内容验证：拒绝盘符/UNC/父路径/反斜杠及逃逸链接，
要求主固件、ELF、配置、收据、回退镜像、源码和状态文件完整，重新验证固件与
源码归档。导出源码包含全部回归依赖，可独立解包后运行统一测试。
连续演示逐轮检查成功 complete 结果和匹配 request ID 的新鲜快照。
所有物理、烧录、三次实机演示和长稳状态仍保持 PENDING。
